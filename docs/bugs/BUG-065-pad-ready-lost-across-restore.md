# BUG-065 — A READY controller re-runs its connection sequence after a savestate restore (title pauses in its controller-disconnected hold)

| Field | Content |
|---|---|
| **ID** | BUG-065 |
| **Title** | A READY controller re-runs its connection sequence after a savestate restore: the pad slot reads DISCONN at boundary 0 and the title parks in its controller-disconnected hold |
| **User-visible symptom** | After loading a gameplay state, animation freezes for ≈2 s, the "controller disconnected" overlay fades in and the UI tables are re-evaluated; every gameplay anchor diverges from the frozen baseline from checkpoint 0 (20,050 RAM words at boundary 2 on artdet) |
| **Scene / savestate** | every gameplay anchor (`save_states/artdet_f37152.ps2st` boundaries 0–600; the ten `ps2state_slot0_*` / `slowspot_*` anchors): PADS section `opened_at=0 stage=2 ready_stamped=1`, restored slot `state 0x06 len 0x20`; NEW `state_b0` `state 0x00 req 0x02` (slots zeroed), `state_b60` `state 0x01`, READY only from ≈boundary 128 |
| **Subsystem** | `input` (primary), `savestate` (secondary) |
| **Root cause** | `PadProtocol::Stamp` (`engine/pad/hle/pad_protocol.cpp`) recomputed the port's stage every boundary as `StageFor(elapsed = now − opened_at, now)`. The PADS section restores `opened_at` in the SAVER's boundary clock (0 on every anchor) while the restored run's `DomainTick()` restarts at 0, so `elapsed` restarted at 0 and the first stamp wrote the DISCONN phase slot (`WritePhaseSlot` → `ZeroSlot`) over the restored READY image, then FINDPAD until `kConfigUntil`/the readiness shortcut. The title reads the zeroed slot as a controller disconnect: `FUN_00176698` → `FUN_00177168` case 0xc returns 0xf → case 0xf `FUN_00174c70` holds (`0x18`) and animates the overlay. OLD never showed this because its pad clock is `g_sceGsSyncV_count`, restored WITH the state (`pad_input.cpp:155-172`: `elapsed = vsync − reg_vsync ≥ 214` on every anchor). |
| **PS2 rule violated** | PADMAN's port state machine is monotonic on the clock: a port that reached STABLE (`scePadGetState` = 6) stays STABLE until `scePadPortClose`/`PortOpen` restarts the connection sequence or the controller is physically removed; time alone never regresses it. (SDK libpad 3.0.1 `scePadGetState` semantics.) |
| **Fix + hatch** | `PadProtocol::Stamp` keeps `Stage::Ready` once the port is READY (`p.stage == Stage::Ready ? Stage::Ready : StageFor(...)`); `RegisterArea` (PortOpen) remains the only path back to DISCONN. No hatch (modelled behaviour; no savestate-format change — `stage` and `ready_stamped` were already saved). Landed by integration stage I8.6-A (2026-10-02). |
| **Regression test** | ctest `PadProtocolRestore` (`tests/pad/test_pad_protocol_restore.cpp`: restore READY + `Stamp(now=0)` keeps `state 0x06 len 0x20`, no zero pass; 6 FAILs without the fix) and root pin `RootAnchorPadReady` (`tests/app/root_anchor_pad_ready.py`: artdet 4-frame leg, `state_b0` slots READY, `state_b2/b3` controller SM case 12, `pad_stage=2,0`) |
| **Source record** | `docs/phases/INTEGRATION_IMPL.md` I8.5-G (`INT-I85G-11K-CLASS-IS-PAD-RESTORE`), `docs/phases/DECISIONS_LOG.md` DP-16 attribution paragraph (gate run 2), I8.6-A record (`int_work/i86a/SECTION.md`, `regions_b2_old1_new2.out`: 20,050 → 62 words at boundary 2) |
| **Triage tips** | If every restored anchor diverges from checkpoint 0 with frozen animation floats, an overlay fading in and the title's controller SM in case 15, dump the PADS slot bytes of `state_b0` (`+0x70` state, `+0x60` length): a `state 0x00 req 0x02` slot on a restored READY port means a device model re-ran its boot sequence from a clock that was rebased by the restore. Any restored device whose stage derives from `now − opened_at` has the same hazard. |
