# BUG-029 — Slide-jump teleports Crash: tick-quantized T0 COUNT tripped the SDK's wrap-anticipation guard

| Field | Content |
|---|---|
| **ID** | BUG-029 |
| **Title** | [S40 / PS2_T0_SUBTICK] T0 COUNT delivered in whole-tick quanta made the game's SDK wrap-anticipation guard misfire every 512 vblank ticks — phantom +65536-count (+1.09 s) clock steps, integrated twice by the physics = the far-jump injector |
| **User-visible symptom** | During a slide-jump, Crash occasionally launches an impossible distance ("far jump" teleport) — rare, periodic, timing-dependent. |
| **Scene / savestate** | Slide-jump repro legs (SLIDEJUMP R1/R2 sessions); mechanism confirmed by the R2 investigator report. |
| **Subsystem** | ee-timing |
| **Root cause** | Our T0 COUNT advanced only at vblank-tick granularity (+9600 per tick, flat between ticks). The game's SDK time code anticipates 16-bit COUNT wrap: seeing COUNT jump by a whole quantum at the wrong phase, its wrap guard concluded a wrap had happened and added 65536 counts (+1.09 s) to elapsed time — every 512 ticks, deterministically. The physics integrates velocity over elapsed time TWICE on that path, so a phantom +1.09 s became a huge displacement: the far-jump injector. |
| **PS2 rule violated** | EE timer continuity: on hardware T0 COUNT advances continuously at BUSCLK/gate resolution between reads — two nearby reads never see a whole-frame step. Quantized delivery of a continuous counter breaks any software that reasons about wrap phase. |
| **Fix + hatch** | Sub-tick T0 COUNT interpolation (`PS2_T0_SUBTICK`, default ON): `SubtickCountLocked()` returns `count_base + floor(cpt * elapsed_fraction)` from a wall stamp `g_vblank_tick_ns` written immediately BEFORE the tick increment (ordering contract: a reader that observed tick N sees a stamp ≥N, so racing reads interpolate ~0 — never fabricate a full-tick jump). Three clamps: intra ≤ cpt−1 (never crosses into the next quantum — tick-domain totals and latched events byte-identical); presentation-only state, never serialized (TIMR codec unchanged); savestate restore re-stamps. Host-side delivery only; zero game-logic clamps. Post-refactor: the "timer subtick" presentation row of DerivedClocks (ARCH §4.7); the deterministic profile turns it OFF (wall-derived low bits). |
| **Regression test** | Slide-jump repro legs clean over 512-tick periods; timer codec byte-identity (TIMR); `test_time_domain` family. |
| **Source record** | `Ps2Recomp/docs/loop_state/SLIDEJUMP_R2_IMPL.md`, `SLIDEJUMP_R2_REPORT.md`, `SLIDEJUMP_R2_REVIEW.md`, `SLIDEJUMP_IMPL.md` (R1) |
| **Triage tips** | A rare, PERIODIC physics anomaly (every N ticks) is a clock-wrap/phase bug, not collision: compute N × quantum and look for 2^k counter boundaries (512 × 9600 ≈ wrap anticipation window). When emulating a continuous counter in quanta, any guest code doing wrap arithmetic is a victim — interpolate delivery, never patch the guest. Mind the stamp/count write ORDER on the producer or the fix fabricates the very jumps it removes. |
