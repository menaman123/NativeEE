# BUG-041 — Asynchronous loader read completes "instantly" in NEW: the title's completion copy runs over a stale stream ring (coldboot slice 60 runaway memcpy), then the load-wait loop never ends the slice

| Field | Content |
|---|---|
| **ID** | BUG-041 |
| **Title** | NEW's host-served asynchronous read made the title's own completion predicate answer "done" before the bytes had landed (a `memcpy` from the stale STREAM ring ran away in slice 60); once completion was modelled faithfully, the title's load-wait loop spun on NEW's slice-frozen headroom clock and never reached the boundary that delivers the read |
| **User-visible symptom** | Cold boot (deterministic profile, memory lane): the leg stops at `frames.fhash` line `60,0x1d609d1b729f12a4`, no boundary-60 image, `run.meta finalized=0`; the process spins one core (first in `memcpy`, after the model in the poll spin `FUN_0017d6b8 → … → FUN_001e3308`). Play build: the post-FMV title load never completes (same class as BUG-038's symptom, different mechanism). |
| **Scene / savestate** | coldboot leg, `--frames ≥ 61 --profile deterministic`; the first asynchronous read (`Hub01.psm`, `dest=0x00fb8900`) issued in slice 60 (I5.1-G Q4 trace; OLD issues it in slice 61 — INT-I410A-ISSUE-SLICE). |
| **Subsystem** | cdvd-loader — secondary: ee-timing (the frozen T0 headroom query) |
| **Root cause** | Two defects of our runtime, one behind the other. (1) **Completion visibility.** On retail an asynchronous read is a STREAM.IRX record on the file's slot: the EE client writes the slot byte (`0x3b3d00 + slot`) to 2 at issue (`FUN_001e1500`), the module lists the slot in every reply while the IOP DMAs the window into the file's callback ring, and the client's reply processor (`FUN_001e1f48`) maps the listing to 1 and, at the first reply that no longer lists it, back to 0. The title's poll (`FUN_002ad110 → FUN_002adaf0 → FUN_001e3308`) reads that byte — 0/3 = done, 2/5 = queued, else active — and ONLY when done runs the completion copy (cb vtable+0x14 = `FUN_002b5dd8`) from the ring to the destination. NEW's `LoaderFileIo::WindowedRead` served the read on the host and never wrote the slot byte, so the byte read 0 = done immediately: the copy ran over a ring still holding the PREVIOUS file's bytes with a stale size ("the Star" — the copy's runaway from stale ring bytes seen in every I5.1-E/G sample: `FUN_002b5dd8 → FUN_001bc920 → memcpy`). (2) **The wait's exit.** With the status modelled (2 at issue, 0 after bytes + ring at delivery, delivered by the boundary model only — `LoaderModel`, slot 4), the title waits as on retail in its load-wait loop `FUN_0017d6b8`: `while (FUN_00191bd0(timer, 1.7 ms)) poll();` (lap 1), then per lap `if (FUN_00191bd0(timer, 1.0 ms)) poll(); … if ($s0 && FUN_00191bd0(timer, 1.0 ms)) next lap`. `FUN_00191bd0` is a HEADROOM QUERY over the T0 clock (`FUN_00191920` → T0 COUNT, folded modulo the frame quantum). On hardware T0 advances in real time and the loop exits on quantum exhaustion. In NEW T0 is a pure function of the emu tick and is frozen inside a slice by design (BUG-014/031/032 removed the wall sub-tick term), so no headroom query turns false inside the slice: the loop never ends slice 60 and the boundary that would deliver the read is never reached (lap counter `$s1 = 36275` observed under lldb). |
| **PS2 rule violated** | (1) An asynchronous IOP read's completion becomes visible to the EE only at the completion-status transition the module's reply protocol defines, and the payload is in place before the status says done (stream order: bytes first, status last). (2) T0 advances in real time during an EE busy-wait; a headroom/quantum predicate over a hardware counter must be able to turn false while the EE spins. |
| **Fix + hatch** | (1) `LoaderFileIo` models the STREAM slot status without a hook (`games/<title>/hle/loader_sync/loader_file_io.{h,cpp}`, I4.10-A): `kSlotIssued = 2` at the asynchronous issue; the delivery `apply` (boundary slot 4 through `LoaderModel`, or the blocking wait's `CompleteNow`) fills dest + ring FIRST and then writes `kSlotDone = 0`. (2) `LoaderSpinLift` (`loader_spin_lift.{h,cpp}`, I4.10-C) over the generated body of `FUN_00191bd0` (Capture/Install as `PadReadinessHook`): at the loop's two load-poll sites (lap-1 spin ra `0x17d724` with `$s0 != 0`; lap ≥ 2 gate ra `0x17d75c` with `$s1 != 0, $s0 == 0`, DP-1 option (a)) and only when `LoaderModel::ShouldYieldPollSlice` re-verifies that the noted poll was held in flight AND the read is still in flight (boundary-only delivery = it cannot land in-slice), the seam answers "no headroom" (v0 = 0) — the exit the hardware's clock would have produced; status, slot table and memory are never touched; every other query keeps the real predicate. HOOK_RECLASSIFICATION class HARDWARE/TIMING HLE (§3.6, sync-wait lift). No env hatch (the single getenv rule); veto = `LoaderSpinLift::Layout::lap2_site_ra = 0`. Counters: `run.meta loader_slot_status=<issued>/<done>`, `loader_spin_lifts=lap1=<n>,lap2=<n>,declines=<m>`. |
| **Regression test** | `LoaderCompletionOrder` (`tests/cdvd/test_loader_completion.cpp`: the REAL recompiled poll reads pending until delivery, done after; the discriminator forces the byte back to 0 while in flight and shows the title saying done over the stale ring). `LoaderSpinLift` (`tests/cdvd/test_loader_spin_lift.cpp`: lifts only under both guards at either site; a read that CAN land in-slice — delivered before the query — or no in-flight read never lifts; other queries are not a decision). Leg-level: the coldboot memory lane passes boundary 60 (`mem.mhash 60,…`, `state_b60.ps2st`). |
| **Source record** | `docs/phases/INTEGRATION_IMPL.md` §I5.1-G (the stall diagnosed), §I4.10-A (the predicate decoded; INT-I410A-STALL-MOVED-TO-SPIN, INT-I410A-ISSUE-SLICE), §I4.10-B (gate evidence), §I4.10-C (the lift); `docs/phases/DECISIONS_LOG.md` DP-1. | **Triage tips** | A coldboot leg whose `frames.fhash` stops at 60 with one core spinning: `sample` it. `memcpy` under `FUN_002b5dd8`/`FUN_001bc920` = the completion copy over a stale ring → check `run.meta loader_slot_status` (issued must equal done at every image) and the slot byte `0x3b3d00+slot` at the last image. `FUN_0017d6b8 → FUN_002aa8d0 → … → FUN_001e3308` with no memcpy = the load-wait loop on a frozen clock → check `loader_spin_lifts` (lap1/lap2 must be > 0 once the first read is in flight; `declines` counts the correctly refused queries).
