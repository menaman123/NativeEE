# BUG-083 — The leg's register-op recorder retained every GIF sink call for the whole run: the host footprint grew ≈ 8–11 MB per title frame (24 bytes per op, every IMAGE quadword of every upload and every vertex) until the OS killed the 13th leg at ≈ 4096 frames (FIXED)

| Field | Content |
|---|---|
| **ID** | BUG-083 |
| **Title** | `RegisterOpStream gs_ops` (the GS-side observable of every GIF stream: `run.meta gsops_hash`, `gsops.ohash`) appended one 24-byte `RegisterOp` per sink call into a `std::vector` that nothing in the leg ever read — only `Hash()` and `Count()` are consumed — so the process footprint grew with the frame count, not with a frame's work: ≈ 5 MB/frame through the boot movies, ≈ 1.5 MB/frame in the in-engine cutscene, ≈ 8.5–11 MB/frame on the title screen (3,981 draws + 135 host→local uploads per frame, each IMAGE quadword one op). `coldboot_attract` (6000 frames) could not finalize on a 24 GB host |
| **User-visible symptom** | P8.22-T: three Release `coldboot_attract` runs ended `frames=4096 finalized=0`, `Killed: 9` with no `[run_bounded]` line (the OS), `vmmap --summary`: `frames 2665 footprint 8.9G peak 18.4G … 4110 25.1G`; the 13-leg battery shows `coldboot_attract RUN-FAIL` (INT-P822T-NEW-TITLE-FOOTPRINT-GROWTH) |
| **Scene / savestate** | Any leg; visible from the first frames (`footprint_watch.py`, Release coldboot: f170 925 MB → f209 2.7 GB → f1280 5.1 GB → f2366 12.0 GB). The OLD probe `old_b2700.ps2st` restores but does not resume (INT-P820B-NEW-BOUNDARY-IMAGE-NOT-RESUMABLE class: `restore.mhash` written, threads relaunched, 0 frames), so the attribution ran on a coldboot leg |
| **Subsystem** | `gs-ir` (`engine/gs/hle/ir/register_op_stream.*`, the recording `GsSink`) wired by the composition root `app/host/ee_bootstrap.cpp`; NOT the texture caches (`DecodeCache` L2 is bounded at 320 MiB / 16384 entries, L1 is evicted by VRAM range), NOT the GL texture pool (96 MiB / 128), NOT the DrawIR queue (bounded ring, payload moved on consumption), NOT the render targets |
| **Root cause** | Attribution (P8.23-A, `int_work/p823a/attr/`): `vmmap --summary` on the live Release leg at frame ≈ 2527: `MALLOC_LARGE 12.1G` virtual in 106 regions (1.8 G resident, 5.7 G swapped) with every other region type < 300 MB — host heap, not GL; `heap -s`: ONE node of `1.25829e+07KB` (12 GiB) among 122 k nodes totalling 13.08 GB — a single container; the ≈ 1.8 GB footprint jumps at f209 and f1280 are its capacity doublings (3 GiB → 6 → 12). `MallocStackLogging` crashes both builds at start (SIGSEGV), so the node was read live: `heap -addresses 'non-object[500000000-]'` → `0xc88000000 (3221225472 bytes)` at f1320; `lldb memory read` shows 24-byte records `{kind, reg, path, pad, aux, lo, hi}` — `0x00030000 0x00098053 …` (Tag, path 3), `0x00025407 …` + 16 image bytes (kind 7 = Image, reg 0x54 = HWREG) — the `RegisterOp` layout (`register_op_stream.h`). `RegisterOpStream::Push` did `hash_ = Fnv1a64(&op, 24, hash_); ops_.push_back(op);` unconditionally; the leg constructs `RegisterOpStream gs_ops` (ee_bootstrap) and reads only `Hash()` / `Count()`; `Ops()` is a replay/test consumer (`DrawIrVerifier::RunOps`, the gif/dmac/vif unit pins). 2800 Release frames = `gsops_ops=` 311,656,456 ops × 24 B = 7.5 GB of records (plus the doubling slack) |
| **PS2 rule violated** | None of the GS's: this is host construction. The recorder's own contract (`register_op_stream.h`): "the hash is the GS-side observable of a GIF stream" — the hash is folded record by record as each call arrives, so the observable never needed the records |
| **Fix + hatch** | P8.23-A: `RegisterOpStream(bool retain_records = true)`; a hash-only stream (`retain_records = false`) folds every record into the same FNV-1a chain and counts it (`Count()` is now a counter, `RetainsRecords()`, `RetainedBytes()`) but stores nothing; `Clear()` also releases a retaining stream's storage. The leg's recorder is constructed hash-only (`ee_bootstrap.cpp`: `RegisterOpStream gs_ops(/*retain_records=*/false)`); tests and replay consumers that read `Ops()` keep the default. No toggle beyond the constructor argument: the hash is identical by construction (same bytes, same chain), so `gsops_hash` / `gsops.ohash` / every lane are unchanged — verified: the live title frame f2519 (`--dump-frames`) has md5 `45eebd45dcd90d17de2af78182a39ed0` = `verify/baseline/title_screen/new_coldboot_f2519_bcd30c2.ppm` (byte-identical) and `RootPlayPolicyInert` / `RootReleaseLanesIdentical` pass. **Census:** `run.meta footprint=b60_mb=,last_mb=,peak_mb=,final_mb=,gsops_retained_bytes=` (the process's physical footprint via `task_info(TASK_VM_INFO).phys_footprint` — what `vmmap --summary` reports — at the 60th boundary, the last boundary, its peak, at finalize) and `footprint_series=b0:…,b60:…` (one sample per 60 boundaries, first 128). Measured after the fix (Release coldboot 2520): `footprint=b60_mb=79,last_mb=462,peak_mb=503,final_mb=463,gsops_retained_bytes=0`, series flat through the title (`b1500:437 … b2460:463`) where before it grew ≈ 512 MB per 60 frames. **Instrument:** `tools/footprint_watch.py` (samples `vmmap --summary` footprint/peak against the leg's `frames.fhash` line count every N seconds; `--pid` attaches; `--selftest`) |
| **Regression test** | `GifRegsStat` → `TestRegisterOpStreamHashOnlyBounded` (`tests/gif/test_gif_regs.cpp`): 64 frames × 8 uploads × 512 IMAGE quadwords + kicks through a retaining and a hash-only stream → same `Count()`, same `Hash()`, hash-only `Ops().empty()` and `RetainedBytes() == 0`; RED before the fix (the pre-fix unconditional `push_back` restored for the probe: `FAIL …:356 hash_only.Ops().empty()`, `FAIL …:357 hash_only.RetainedBytes() == 0`, `GifRegsStat: 2 failure(s)`) → `GifRegsStat: PASS`. `RootFootprintBounded` (`tests/app/root_footprint_bounded.py`, TIMEOUT 600, SKIP 77 without the title files): a deterministic headless coldboot `--frames 400` must report `gsops_retained_bytes == 0`, `peak_mb <= 1024` and a tail growth `b300 → b360 <= 120 MiB` (measured `+1 MiB`; before the fix the recorder alone added ≈ 187 MiB per 60 boot-movie frames and ≈ 1.2 GB by frame 400). `RootFootprintBoundedSelftest`, `ToolsFootprintWatchSelftest` |

| **Triage tips** | A footprint that grows with the frame count while every cache reports a bound is a container nobody bounds: `vmmap --summary <pid>` names the region type (MALLOC_LARGE = a few huge nodes), `heap -s <pid>` the node sizes (one giant node = one vector; ≈ 2× jumps in the footprint series = its doublings), `heap -addresses 'non-object[<bytes>-]'` its address, and `lldb -p <pid> --batch -o "memory read -s4 -fx -c 32 <addr>"` its record layout when `MallocStackLogging` is unavailable. Read `run.meta footprint_series=` first: flat after the boot movies = bounded |
