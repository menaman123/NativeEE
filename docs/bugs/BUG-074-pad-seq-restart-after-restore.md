# BUG-074 — After a savestate restore the pad slots' sequence counter (+0x58) restarted at the boot value: NEW's `PadProtocol::seq_` (and OLD's `s_seq`) is a process-lifetime counter the PADS section never carried, so every restored leg published 2/3 at the first stamp while the restored pad area already held the console's counter (artdet anchor: 1552/1553)

| Field | Content |
|---|---|
| **ID** | BUG-074 |
| **Title** | The pad slot sequence counter restarts at 1 after a savestate restore instead of continuing from the counter in the restored pad area |
| **User-visible symptom** | None in play (libpad's reader picks the slot with the larger counter and the title's pad state machine only needs the counter to ADVANCE — INT-I86A-PAD-READY-STICKY); visible as 4 differing words per restored boundary image at `pad_area+0x58` / `+0xD8` (`0xbb05d8` / `0xbb0658`) against the frozen OLD probes (INT-I86A-PAD-SEQ-NOT-SAVED: OLD 5 vs NEW 4 at artdet b2, 63 vs 62 at b60). |
| **Scene / savestate** | Every anchor (all 11 carry port 0 open at `0xbb0580`, READY, `ready_stamped`): `artdet_f37152.ps2st` slot0 seq 1552, `ps2state_slot0_f36935` 50336, `f44111` 58023, `f57292` 691561 (`int_work/p811a/seq_probe.py`). |
| **Subsystem** | `savestate` (primary: the PADS decode) + `input` (secondary: `PadProtocol`). |
| **Root cause** | NAMED. `PadProtocol::Stamp` pre-increments `seq_` and publishes `seq_` / `seq_+1` into the two slots; `seq_` was initialised to 1 at construction and `PadsSection::Restore` never set it (the PADS record has no counter field — `pads_section.h` wire layout), so a restored process published 2/3 at its first stamp. OLD has the same defect: `host_app/pad_input.cpp:829` `static uint32_t s_seq = 1; s_seq++;` is a process static that `PadInput_SerializeState` / `PadInput_RestoreState` (`:1015-1053`) neither save nor restore; OLD's baseline value at b2 (5) is the fresh OLD process's counter after its boot boundaries plus the leg's — not the console's. The console's counter at the save instant IS in the image: the pad area's +0x58 words are PADMAN's frame counter as last DMA'd. |
| **PS2 rule violated** | libpad / PADMAN (SDK 3.0.1): the pad data buffer's `frame` word (+0x58 of each 128-byte slot) is PADMAN's monotonically increasing frame counter, written by the IOP's per-vsync DMA; libpad's reader selects the slot with the larger counter. A console state restored from an image continues that counter from the value the buffer holds — PADMAN never restarts it while the port stays open. |
| **Fix + hatch** | LANDED (P8.11-A, 2026-10-04): `PadsSection::Restore` DERIVES the protocol's counter from the restored pad area — slot 0's +0x58 word of the first open port (`PadsSection::Reader` over guest RAM; the memory sections restore ahead of PADS in the registry order) — so the next stamp publishes image+1 / image+2; the format is unchanged (166 bytes, every frozen anchor decodes the console's value); `PadProtocol::kSeqBoot` names the boot value and `SeedBootDefault` (no PADS section) resets to it. Toggle: `PadsSection::SeqRestore` (`FromImage` default = the console; `Restart` = the original's restart-at-1), the one constructor line in `app/host/ee_bootstrap.cpp`. Census: `run.meta pad_seq=<live>,<derived>`. Decision DP-24 (`docs/phases/DECISIONS_LOG.md`). |
| **Regression test** | `PadProtocolRestore` (`tests/pad/test_pad_protocol_restore.cpp`: `restore_derives_seq_from_slot0_word`, `first_stamp_after_restore_publishes_image_plus_1`, `slot1_publishes_image_plus_2`, `third_stamp_publishes_image_plus_3`, the `Restart` toggle `restart_toggle_first_stamp_publishes_2_3`, the no-reader / no-port / absent-section arms); `RootAnchorPadReady` (`tests/app/root_anchor_pad_ready.py`: `state_b0 seq slot0=1553 slot1=1554 (anchor 1552)`, `state_b2 seq slot0 @0xbb05d8 = 1555 (anchor 1552 + 3)`, `state_b3 … 1556` — RED on the gate-S6 binary: `state_b0 seq slot0=2 slot1=3`, `state_b2 … = 4`, `state_b3 … = 5`, `int_work/p811a/rootpin_before_s6.out`). |
| **Source record** | `docs/phases/PHASE8_IMPL.md` P8.11-A; `int_work/p811a/{PROGRESS.md,SECTION.md,seq_probe.py,score_probes.out,rootpin_before_s6.out,rootpin_after.out}`; `docs/phases/INTEGRATION_IMPL.md` INT-I86A-PAD-SEQ-NOT-SAVED (I8.6-A). |
| **Triage tips** | A restored-leg word that differs from OLD by a SMALL constant at a pad-area offset is a host-side counter that the savestate does not carry — check whether the guest buffer already holds the console's value before adding a section field (the buffer is the authority; a field would duplicate state). Compare `run.meta pad_seq` with `seq_probe.py` on the anchor: `derived` must equal the anchor's slot 0 word. |
