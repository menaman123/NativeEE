# BUG-086 — The loader seam fills the file stream's ring once per RECORD instead of once per 128 KB WINDOW (the Default.rm2 ring of coldboot boundary 112: 900 fills for 19)

| Field | Content |
|---|---|
| **ID** | BUG-086 |
| **Title** | `LoaderFileIo::WindowedRead` (the seam standing in for the title's windowed reader `FUN_002aac80`) issued one read record per request and DMAed each record's bytes to the callback stream's base: 900 fills of the Default.rm2 ring inside coldboot boundary 112 where the console fills it 19 times (once per 128 KB window of the file) and serves the records from the ring by the title's own copy-out |
| **User-visible symptom** | None on screen (every record's destination received the right bytes). In memory: the stream ring `0x948540-0x968540` held the tails of record-sized fills (the largest `0xa0e4`, then 90,064 zero bytes) instead of the console's last two windows; the ring-valid bit `fs+0 & 0x40000` never rose, `fs+0xc` (the fill's start) was never written, the cursor was reset per record; the drive timeline carried ~900 records where the console's carries 19 (every record a STREAM slot issue + wait). The coldboot b120 probe pair carried the class `SECOND-RING` (17,888 words vs the original tree, itself not the console). |
| **Scene / savestate** | Deterministic coldboot, boundary 112 (the `Startup\Default.rm2` load: 900 records of 0xc–0xa0e4 bytes, `tests/cdvd/fixtures/loader_requests_coldboot121.tsv`); the console's timeline `int_work/p828a/pcsx2_splash_plus{40,70,90,100}.p2s`, `pcsx2_splash_plus110_rec159.p2s` (EE images `pcsx2_*_ee.bin`). |
| **Subsystem** | `cdvd-loader` |
| **Root cause** | The seam (`games/<title>/hle/loader_sync/loader_file_io.cpp`) modelled only the "ring window not valid" branch of `FUN_002aac80` (`0x2aafa4-0x2ab0a8`): every window below the stream's capacity became its own DMA of `size` bytes to the ring's base with the completion copy staged. The retail body keeps the ring as a CACHE of one window of the file: `fs+0xc` = the BD-absolute start of the fill most recently issued, `fs+0 & 0x40000` = the ring holds a window, the fill is `min(eof − start, cap)` bytes (`0x2aae04-0x2aaeb4` on a straddle, `0x2aafd0-0x2ab04c` on a miss); a request inside `[fs+0xc, fs+0xc + cap)` seeks the cursor (`cb vtbl+0x64`) and is served by the copy-out (`cb vtbl+0x14` = `FUN_002b5dd8`) with no record; a straddle copies the tail and chains the next fill at `pos + tail`; the valid bit drops when the cursor reaches the ring's end (`0x2ab0ec`). Measured live on PCSX2 (P8.28-A, `int_work/p828a/fs0xc_trace.md`): the chain `+0x0, +0x20000, +0x40000, +0x76d18 … +0x1ddef8, +0x22ba32, +0x24ba32 (EOF, 0x15fe7 bytes)`. |
| **PS2 rule violated** | `[title-idiom]` — the title's own stream layer: STREAM.IRX DMAs a whole window into the EE ring once, and the EE serves the following records from it. The seam's per-record DMA is a different drive timeline (record count, slot issues, waits) and a different ring image from the console's. |
| **Fix + hatch** | `LoaderFileIo::RingCacheRead` (the five steps of the retail body over the title's own words: `fs+0`, `fs+0xc`, `fs+0x10/+0x18`, `cb {base, cursor, cap}`; no host-side ring state; the copy-out through the stream's vtable; one record per fill on the model's drive timeline) behind the Config key **`loader.ring_cache`** (bool; `off` = the per-record seam). **Status: FIXED — default `on` since P8.31-A (2026-10-06)**: DP-5 (b) attempt 2 KEPT under the DT-7 score (P8.30-T's re-score of the attempt-2 gate under the per-run scene pairing: unbooked `(0, 20064977)` vs S11 `(0, 20253916)` → BETTER; raw `(0, 20084447)` vs `(0, 20258815)` → BETTER; record APPROVED on re-review). `--set loader.ring_cache=off` keeps the per-record seam reachable; the unit tests whose meaning is that seam (`LoaderSeams`, `LoaderCompletionOrder/Oversized/Module`) set it explicitly. The wait seam's completion copy runs under the ring rule in either delivery visibility (the retail wait runs it unconditionally). |
| **Regression test** | `LoaderRingCache` (unit, explicit `--ring-cache on|off`: the 906-request coldboot list replayed over the disc image → 19 records not 906, the console's `fs+0xc` chain, the console's staged words at `+40`/`+90`, the ring == `pcsx2_plus90_ee.bin` after the `+0x1ddef8` fill and == `pcsx2_rec159_ee.bin` after the EOF fill; `--ring-cache off` is the red side: 902 records, 11 assertions fail); `RootLoaderRingCache` (a 121-frame coldboot leg with the key on — passed explicitly, also the default since P8.31-A: state_b120's ring and `fs` words equal the console's rec159 image; `loader_ring=on,hits=887,straddles=12,misses=12,fills=24,direct=1`). |
| **Source record** | `docs/phases/PHASE8_IMPL.md` P8.28-A (the console read, the gap named) and P8.29-A (the model, `int_work/p829a/`: `requests_b112.tsv`, `replay_model.py`, `pin_green.log`/`pin_red.log`, `leg_on/`, `attr_before.log`/`attr_after.log`); DECISIONS_LOG DP-5 (b); P8.30-T (the DT-7 re-score, `int_work/p830t/rescore/`) and P8.31-A (the default flip, `int_work/p831a/`). |
| **Triage tips** | A ring whose content is the tail of many small fills (data ending exactly at `base + largest request`, zeros past it) says the fill rule is per request; the console's ring always holds whole windows (`cap` bytes, or `min(remaining, cap)` at EOF) and `fs+0xc` names the window. Compare the enqueue COUNT per load against the console's fill chain before comparing bytes. A seam that stands in for a title body must keep the title's bookkeeping words (`fs+0xc`, the valid bit, the cursor) — later title code reads them. |
