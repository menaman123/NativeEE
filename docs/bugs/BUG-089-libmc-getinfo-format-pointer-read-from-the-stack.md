# BUG-089 — The type registry held 8 of the console's 28 entries: the libmc `sceMcGetInfo` row read its fifth argument from the stack and stored `format = 1` into the title's MC-manager header, collapsing the slot count the UI constructor iterates from 4 to 1

| Field | Content |
|---|---|
| **ID** | BUG-089 |
| **Title** | 20 type-registry descriptors the hardware builds by record `0x36` (12 × 92 B of `FUN_001a8268`'s class, 4 × 148 B, 4 × 156 B, with their 576 B / 272 B tables) were never built on NEW: the 28-pointer registry table at `0xba8a60` held 8 entries, the page pool 114 class-22 (92 B) chunks against the console's 126 — because NEW's `LibmcBindings::GetInfo` dereferenced the caller's stack word `sp+0x10` as the `*format` out-pointer |
| **User-visible symptom** | None found on screen in the probed windows. In memory: every page-pool page popped after the registry's pages sat at another index than on the console (P8.32-A: the first divergent page pop vs the console was page 106 — console class 56/576 B, NEW class 52 — and every later pop shifted −3 pages), which is what kept the META-ARENA-off decision (DP-31) from being scored honestly; the save/load UI's per-slot descriptor set was built for one memory-card slot instead of four |
| **Scene / savestate** | Deterministic coldboot, boundaries 60 and 120 (`int_work/p833a/leg_watch/state_b{60,120}.ps2st` before the fix; `leg_{off,on}/state_b120.ps2st` after) against the PCSX2 images `int_work/p828a/pcsx2_plus40_ee.bin` (record `0x36`, boot-SM case 1) and `pcsx2_rec159_ee.bin` (record `0x159`, the matched b120 moment); live: PCSX2 from `beginning_splash.p2s` / `323350_init.p2s` |
| **Subsystem** | `ee-kernel` (the libmc SDK row's calling convention); secondary `ee-mem` (the page pool's layout downstream) |
| **Root cause** | The title's UI constructor `FUN_001700d8 → FUN_00164ae8` registers four type descriptors per memory-card slot its MC manager counts: the loop bound is the slot-count nibble of the manager's header word (`lw v1,0x14(s7); lw v0,(v1); andi v0,0xf` at `0x164b58-0x164b60`, s7 = `*(gp-0x7dcc)` = the world object, `+0x14` = the MC manager at `0xbe0a20`), which `FUN_002a2700` builds as 4 (`FUN_00169348`: `li a1,4` — 2 ports × 2 slots). Each iteration's registry object owns a 4-entry table; the seven tables are vended back to back at `0xba8a60` = the 28 slots. NEW's `engine/mc/hle/libmc_bindings.cpp` `GetInfo` read the fifth argument of `sceMcGetInfo(port, slot, *type, *free, *format)` as `memory::read<uint32_t>(sp + 0x10)` — the o32 convention — while the EE SDK passes it in `t0` (the title's call site `0x2a6d28`: `addiu t0, a2, 8` → `0x2e7d70`). The stack word at `sp+0x10` at that call is the caller's saved MC-manager pointer `0xbe0a20`, so the row's `format = 1` store landed in the manager's header word: `0xe004 → 0x1` in the very frame the manager was built (b59, `leg_diag/watch.log`: `FUN_002a2700+0xd9c:0x0->0xe004` then the host writer `WordWatch::Record … 0xe004->0x1`), every frame after. The UI constructor then ran its loop once (1 × 4 = 4 slots + the 4 another registrar fills = 8), and the 20 descriptors the hardware builds (console nibble 4 at `beginning_splash`, `+40`, `+70`, `+90`, `+100`, `rec159`) never existed on NEW. The real `*format` cell `0x2e7d70` was never written. OLD was not affected (its `sceMcGetInfo` HLE wrote `0x2e7d70`; OLD's own `[MC-TICK]` log keeps the nibble 4 through vsync 384) — this was a NEW transplant defect, not inherited |
| **PS2 rule violated** | The EE calling convention (ee-gcc / SDK libraries): the first eight integer arguments travel in `a0–a3, t0–t3`; a five-argument SDK call leaves nothing on the caller's stack. An HLE row that reads an argument from `sp+N` reads whatever the caller spilled there and writes through it |
| **Fix + hatch** | `engine/mc/hle/libmc_bindings.cpp` `GetInfo`: `format_ptr = A(ctx, 4)` (register t0, as `GetDir`'s `max[t0]`/`table[t1]` already did) behind Config `hle.libmc_format_in_t0` (`LibmcBindings::SetFormatInT0`, wired by `app/host/ee_bootstrap.cpp`, run.meta `libmc_format_in_t0=`). **Default `off` (the inherited stack read, the frozen baselines' observable):** with `on` as the default the full suite turned six Root pins red (`RootMixesFmvPcm`, `RootBindsFmvRows`, `RootPlayPolicyInert`, `RootTitleScreenEffects`, `RootPlayFmvPresents`, `RootAttractCutsceneFrames`; `int_work/p833a/ctest_full.log`: `99% tests passed, 6 tests failed out of 451`) — with the slot count 4 the title's boot flow no longer reaches the FMV in 400 frames on NEW's libmc model (`fmv=… inits=0`, `fmv_pictures_served=0`, `sceMcGetInfo@0x2c5940:61` per 121 frames), a SECOND gap of the MC model (the hardware plays the FMV with the nibble 4) that the next stage attributes before `on` can be kept (policy (2)/(3)) |
| **Regression test** | `LibMcSaveFlow` (both arms: the default stack arm stores `format = 1` into the sentinel object behind `sp+0x10` and leaves `*format` at −1; the t0 arm leaves the sentinel at `0xE004` and writes `*format = 1`); `RootTypeRegistryComplete` (`tests/app/root_type_registry_complete.py --arm on`: coldboot b120 with `--set hle.libmc_format_in_t0=on` vs `pcsx2_rec159_ee.bin` — MC slot-count nibble 4 == 4, 28/28 registry slots with the console's class signatures, class-22 USED chunks 126 == 126; `--arm off` RED: nibble 1, 19/28 slots (8 of the registry's), 114 chunks); `Coretest_config` + `SettingsTableReproducible` (the key) |
| **Source record** | `docs/phases/PHASE8_IMPL.md` P8.32-B (deliverable 2: the census and the hardware chain) and P8.33-A (`int_work/p833a/`: `reg_chain.out`, `leg_diag/watch.log`, `con_mcsync.out`, `red_pin.log`, `green_pin.log`, `page_diff.out`); DECISIONS_LOG DP-31 status (the re-score it unblocks) |
| **Triage tips** | A `--watch-word` census line whose writer is `WordWatch::Record` (no recompiled frame) on a word the title owns is an HLE row storing through a pointer it mis-read: check the row's argument reads against the EE convention (`a0–a3, t0–t3`), never `sp+N` for arguments 5–8. A loop bound read from an object header nibble (`andi 0xf`) that differs from the console names the header's writer, not the loop. A registry/table whose NEW count is a multiple of a per-iteration constant (8 = 2 × 4) short of the console's (28 = 7 × 4) is a loop-count gap: find the bound's source word on both sides |
