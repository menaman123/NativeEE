# BUG-064 — PSMT4 host→local uploads write no nibble into VRAM (OLD `WriteHWReg` has no PSMT4 store); the RGBA8 side copy of a T4 upload is half undefined bytes

Filed by integration stage I7.1-A (2026-10-01) for the Phase-6 BUG-KB candidate **P6-T4-UPLOAD-DROP** named by the PHASE6 INTEGRATION CHECKLIST item 7 row L7 (`docs/phases/PHASE6_IMPL.md:3867`) but not filed by IDOC-A (its review MAJOR #1); the record stays the evidence.

| Field | Content |
|---|---|
| **ID** | BUG-064 |
| **Title** | PSMT4 host→local uploads write no nibble into VRAM (OLD `WriteHWReg` has no PSMT4 store); the RGBA8 side copy of a T4 upload is half undefined bytes |
| **User-visible symptom** | None observed on this title: the GS corpus census shows no 4-bpp upload (`grep -oh 'bpp=[0-9]*' OLD/gs_corpus/census/*.txt` → `50 bpp=32` only, `PHASE6_IMPL.md:536`). Should a T4 upload ever be issued, a texture read back from local memory through another view (CLUT-as-CT32, T4→CT32 conversion, T4HL/T4HH aliasing) would show stale or zero VRAM content — `wrong-texture` / `patchwork/blocks` |
| **Scene / savestate** | n/a — no anchor reproduces it: no corpus leg carries a `bpp=4` upload. The invariant pin is unit-level (`GsTransferCursor`) |
| **Subsystem** | `gs-vram` (primary: the missing local-memory store); `gif-vif-dmac` (secondary: the HWREG image-transfer path) |
| **Root cause** | Three halves (`PHASE6_IMPL.md:94`). (1) VRAM half: OLD `gs_state.cpp WriteHWReg` computes the PSMT4 address (`:5116-5117`, `:5368-5369`) but neither the legacy loop (`:5436-5445`) nor the `PS2_XFER_FAST` word path (`:5160-5169`) has a `0x14` store case (`:5331-5527` `default: break`): the transfer cursor advances, the pages are stamped and the upload job is emitted, but no nibble is written. (2) Linear-payload half: OLD fills `linear_pixels` per "pixel" with `(value>>(p*8))&0xFF` for p<16 — a shift ≥ 64 for p ≥ 8 is undefined behaviour, so the RGBA8 copy of a T4 upload is 8 defined + 8 undefined bytes per word. (3) Watermark half: the per-pixel `NoteVramWrite` watermark and the upload epoch still advance as if the data had landed. NEW `TransferEngine::StorePixel` reproduces half (1) bug-compatibly (no nibble; cursor/pages/epoch advance) and does NOT reproduce half (2) — undefined behaviour has no bit-exact twin — storing the nibble the cursor decoded in the linear default arm instead |
| **PS2 rule violated** | GS local memory accepts host→local image data in every PSM the BITBLTBUF.DPSM names; a PSMT4 transfer stores one 4-bit index per pixel at the PSMT4 block/column layout (GS User's Manual §8.4 / local memory formats). An upload that advances TRXPOS/TRXREG state without writing the destination is not a legal GS behaviour |
| **Fix + hatch** | Not fixed — reproduced (half 1) as the bug-compatible arm pinned by `GsTransferCursor`; the manual's layout writer exists (`Swizzle::LinearToVram`, P2-T4) and would replace the no-store arm once an accepted-difference row is opened. No hatch (no runtime flag); the switch is the EQUIVALENCE_PLAN §7 protocol: candidate rows **P6-T4-UPLOAD-DROP** (`docs/design/EQUIVALENCE_PLAN.md:254`, *Pending / candidate — NOT filed*) and **P2-T4-HWREG** (`:243`, *Pending / candidate*) |
| **Regression test** | ctest `GsTransferCursor` (pins the cursor/page/epoch advance with no nibble); oracle `OgGsFormatOracle_F3F4` reports the fact as `PSMT4 F3 NO-WRITE`. The accepted-difference row is the INVARIANTS work item should a T4 upload ever appear on a leg |
| **Source record** | `docs/phases/PHASE6_IMPL.md:94` (findings row P6-T4-UPLOAD-DROP, 6B), `:536` (ledger row rewritten with the three halves + census fact), `:3867` (INTEGRATION CHECKLIST item 7 row L7 naming the `docs/bugs/` entry); `docs/design/EQUIVALENCE_PLAN.md` §7.1 rows P2-T4-HWREG (`:243`) and P6-T4-UPLOAD-DROP (`:254`) |
| **Triage tips** | If a texture sourced from a PSMT4 upload reads as stale/zero VRAM while `gs_vram_epoch` advanced, suspect this no-store arm before the texture cache; `OgGsFormatOracle_F3F4` printing `PSMT4 F3 NO-WRITE` is the fingerprint. Do not "fix" it silently in `StorePixel`: the frames/mem lanes against OLD would diverge — open the accepted-difference row first. |
