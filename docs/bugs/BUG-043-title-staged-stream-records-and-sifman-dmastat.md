# BUG-043 — Title-staged STREAM records vs boundary-only IOP progress in NEW; co-root-cause: sifman `sceSifDmaStat` returned 0 (= pending forever) to the recompiled STREAM.IRX CD worker

| Field | Content |
|---|---|
| **ID** | BUG-043 |
| **Title** | Two STREAM read records the title stages ITSELF (the whole-file loader `FUN_002ab160 → FUN_002ad9a8 → FUN_001e69a8`, type 0x7e; the level loader `FUN_002ad0b0 → FUN_002ada68`, type 0x7f) are served by the recompiled STREAM.IRX, whose completion reaches the EE only through the sceSifCallRpc end-callback and the IOP pump — both boundary duties in NEW — while the title's wait `FUN_002ad1a0` is an intra-frame spin, so the frame never ends (DP-6). Underneath it, NEW's sifman HLE `SifmanModule::sceSifDmaStat` answered `0` (SDK: queued) where the module's post-DMA poll waits for a NEGATIVE status (SDK: −1 = complete), so even with the IOP running inside the wait the CD worker never finished a job and the module's reply never left (DP-7). |
| **User-visible symptom** | Cold boot (deterministic profile, memory lane): the leg passes boundary 60 (`mem.mhash 60,0x8d000860de96f0b5`) and stops at `frames.fhash` line 73 with `run.meta frames=64 finalized=0`, no checkpoint 120 (I4.10-F/G/I/J: byte-identical images across four runs). | **Subsystem** | cdvd-loader (wait seam) · iop-hle (sifman) |
| **Root cause** | (1) **Timing surface.** On hardware the IOP runs concurrently and the SIF interrupt delivers the client's end-callback (`FUN_001e6968 → FUN_001e1f48`, which ages the slot byte 2 → 5/1 → 0) while the EE spins in `FUN_002ad1a0` (retail lap: `Ship(0)` + `FUN_001e37c8(slot, 0)` until `fs+2 & 1` clears). NEW's cooperative IOP kernel ran only at boundary slots 5/6 (`IopModuleTable::PumpAtBoundary`, `EeRpcServer::Service`) and the end-callbacks at slot 4 (`RpcRouter::CompletePending`); the seam replacing `FUN_002ad1a0` (`LoaderFileIo::WaitReadComplete`) only completed HOST-served reads (`LoaderModel::CompleteNow`) and returned with the poll still pending for module-owned records. (2) **The constant.** `engine/iop/hle/sifman/sifman_module.cpp` `sceSifDmaStat` wrote `gpr[2] = 0`. The SDK contract (sifman `sceSifDmaStat(id)`): −1 when the transfer identified by `id` has completed, 0 while queued, 1 while in progress. The recompiled module's CD worker (`iop_recompiled.cpp` labels `0xd54c-0xd560` and `0xd4b4-0xd4dc`): `CpuSuspendIntr; a0 = *(s1+0x3310) (the id sceSifSetDma returned); v0 = sceSifDmaStat(a0); bgez v0 → CpuResumeIntr, DelayThread(0x14), retry` — exits only on a negative status. NEW's own EE-side face already pinned −1 (`tests/ee/test_syscall_table.cpp:108`); OLD's IOP stub (`OLD/host_app/iop_stubs.cpp:645`, read-only) carries the same `0` but OLD served STREAM records through its own HLE RPC handler, never through the module's worker, so it was never exercised there. (3) **The lap's call.** The slot byte changes ONLY in the client's reply processor; the module answers (and its job engine advances) only on a call. The seam's first lap shape shipped only when records were staged (`ShipStagedRecords`), so a lap with nothing staged could never see the record retire; retail's lap calls `Ship(0)` unconditionally (`FUN_001e2958(0)` itself skips while the previous call is outstanding, `sceSifCheckStatRpc`). |
| **PS2 rule violated** | (1) The IOP progresses concurrently with an EE spin and the SIF interrupt lands the RPC end-callback mid-spin; a cooperative IOP must be given that progress inside the EE park loop (HOOK_RECLASSIFICATION §3.6, the completion-visibility model; the sync-wait lift class). (2) sifman `sceSifDmaStat` reports a completed transfer as −1. (3) The STREAM client's wait lap issues its status call every lap. |
| **Fix + hatch** | (1) I4.10-I (DP-6 orchestrator decision (a)): `LoaderFileIo::WaitReadComplete` — when the flag is up, no host read is in flight and the slot byte is module-owned (`Layout::module_slot_states` = {1, 2, 5}), up to `Layout::max_module_laps` (8) laps of `Deps::pump_module(ctx)` (the root binds `IopModuleTable::PumpFromParkLoop` → `EeRpcServer::Service` → `PumpAfterEeService` → `RpcRouter::CompletePending`, `app/host/ee_bootstrap.cpp`), then the title's own poll (`FUN_002adaf0`) decides; the flag is lowered only by that poll; census `run.meta loader_waits_module=<waits>/<laps>`. (2) I4.10-K (DP-7 (a)): `SifmanModule::sceSifDmaStat` → `kDmaStatComplete = -1` for every id (the copy ran inside `sceSifSetDma`; ids are not tracked — an unknown id is complete too, as the SDK reports once its ring recycled the entry); `DmaStatPolls()` census. (3) I4.10-K: each lap runs the REAL `Ship(0)` (`fn_ship = 0x1e2958`, a0 = 0) unconditionally. No hook on a title function; no status faked; no hatch. Revert = unbind `Deps::pump_module` (the seam then returns as the poll says). |
