# BUG-067 — The texture decode fallback copied all of VRAM and built the decode inputs BEFORE the cache lookup, on every textured draw (99 % of which hit)

| Field | Content |
|---|---|
| **ID** | BUG-067 |
| **Title** | `TextureResolver::DecodeFallback` read the composed 4 MiB VRAM view and materialised per-call byte vectors (`window`, `clut`, `mip_win`) before the L1/L2 content-key lookup, although only a miss (`DecodeAndUpload`) reads the view — ≈ 5.6 GiB of memcpy per gameplay frame on a 99.3 % hit rate |
| **User-visible symptom** | The gl window ran the artdet gameplay anchor at 612–701 ms/frame (Debug preset; `video.backend=soft`, which runs no DrawIR consumer at all, 103 ms/frame): the EE thread spent 77.5 % of its time inside `DecodeFallback` with the actual decode at 0.4 %; under the play-mode wall lock the frame's work exceeded a field at 181 of 240 boundaries (`pace_late`) |
| **Scene / savestate** | artdet anchor `save_states/artdet_f37152.ps2st`, deterministic headless gl leg `--frames 30` (`int_work/i810b/new_gl30 wall_ms=21350`, 1609 draws/frame, 1429 `DecodeFallback` calls/frame); any textured scene |
| **Subsystem** | `gs-texsrc` (primary: `engine/gs/hle/texsrc/texture_resolver`), `render-backend` (symptom: the pipeline runs inline on the EE thread inside the GIF kick) |
| **Root cause** | `DecodeFallback` (`texture_resolver.cpp`, the I8.10-B per-line sample): `view_.resize(4 MiB); vram_.ReadView(0, kBytes, view_)` (15.1 % of the EE thread — `ReadView` is a memcpy plus the pending-shadow page overlay, `vram_image.cpp`) then `std::vector<uint8_t> window(win_size)`, `clut.resize`, `mip_win[i].resize` per level (6.9 + 5.1 + 13.5 %) and their destructors at function exit (23.6 %: the Debug preset's per-byte `allocator_traits::construct/destroy` loops), then `ContentKey::Compute` (11.7 %, the key's inherent hash of the footprint window) — all before `cache_.L1Find`. The cache itself was sound (L1 hit 98.0 %, L1+L2 99.3 %; the key is content-addressed and TBP-free, the invalidation per draw/EE upload is correct). |
| **PS2 rule violated** | None of the GS's: this is host construction. The resolver's own contract (`content_key.h`): the key covers exactly the decode's inputs — the hashed window bytes, the CLUT page, the mip windows — so nothing beyond those bytes is needed to decide a hit; the composed view is a decode input only. |
| **Fix + hatch** | I8.11-A (2026-10-02): the pre-lookup path reads ONLY the key's inputs — the level-0 window (its row band for a UV sub-rect), the CLUT page of an indexed read, the authored mip windows — into grow-only scratch members (`window_`, `clut_page_`, `mip_win_[]`, `mip_in_`; `Scratch()` resizes once, never per call), computes the SAME `ContentKey::Compute` (same bytes, same seeds → same hash values) and looks up; the composed 4 MiB `ReadView` moved into `DecodeAndUpload` (miss path only; nothing writes VRAM between the key's reads and the decode, so the view holds exactly the hashed bytes). No key, no pixel and no cache-policy change. Census `TextureResolver::Census` (`lookups`, `l1_hits`, `l2_hits`, `decodes`, `prep_bytes` = bytes read before the lookup, `view_bytes` = composed-view bytes read for decodes) → `run.meta texres=…`. Measured (artdet gl `--frames 30`, Debug, same host load): `wall_ms` 18360 → 9893 (612 → 330 ms/frame); `texres=lookups=41459,l1_hits=40611,l2_hits=551,decodes=297,prep_bytes=1812766720,view_bytes=1245708288` (≈ 44 KiB prepared per lookup, the view read 297 times instead of 41459). The residual per-lookup cost is the footprint hash — the content-key design's price (a tuple → key short-circuit on the footprint's `WindowEpoch` would remove it; a design choice, not taken). |
| **Regression test** | ctest `Texsrc_DecodeFallbackPrepBytes` (`tests/gs/texsrc/test_texsrc.cpp prep_bytes`, FakeBackend + a real `VramImage`: 64 identical CT32 draws → `decodes == 1`, `l1_hits == 63`, `prep_bytes == 64 × footprint` (< one VRAM copy), `view_bytes == 4 MiB` (the one decode); an L1 eviction → L2 rebind without a decode or a view read; an indexed read adds exactly its 8 KiB CLUT page). Byte identity: `RootPlayPolicyInert` (coldboot 130 gl frames lane identical to the fixture) and the artdet 30-frame `frames.fhash` `cmp` identical before/after (`int_work/i811a/art30_before`, `art30_after`). |
| **Source record** | `docs/phases/INTEGRATION_IMPL.md` I8.10-B (`INT-I810B-TEXCACHE-HITS-99PCT`, `INT-I810B-DECODEFALLBACK-PRE-LOOKUP-COST`), `docs/phases/DECISIONS_LOG.md` DP-16 Attribution (b) + Status (b), I8.11-A record (`int_work/i811a/SECTION.md`) |
| **Triage tips** | When a cache reports a high hit rate yet its lookup dominates a profile, sample per call-site LINE inside the lookup function (macOS `sample` + `sample_agg.py`): preparation done unconditionally before the hit test is invisible to hit/miss counters. Keep a bytes-copied counter beside the hit counters (`prep_bytes` vs `view_bytes` here) so the O(texture)-per-hit contract is pinned, not assumed. In Debug presets per-call `std::vector<uint8_t>` locals cost per-byte construct/destroy loops — reuse grow-only members. |
