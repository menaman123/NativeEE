# BUG-038 — Cold boot never reaches the title screen under the default-ON EE run token (stuck in boot-SM case 6 after the intro FMV)

| Field | Content |
|---|---|
| **ID** | BUG-038 |
| **Title** | With `PS2_EE_RUNTOKEN` ON (shipped default) a cold boot in the user env stays in boot-SM case 6 after the intro FMV; with `PS2_EE_RUNTOKEN=0` the boot-SM edge 6→7 lands at vf 2629 and the 3D title scene starts rendering |
| **User-visible symptom** | Cold boot: logos and intro FMV play normally (audio complete: 897,024 FMV audio frames in both arms), then the title screen never appears — black/hold presents forever (presents keep flowing via the CRTC injector, so nothing times out and no FATAL is printed). |
| **Scene / savestate** | Cold boot only (no savestate). Repro legs (user env, `build/host_app/host_app`, round-1A final binary 21:25:53): ON: `--bench-frames 3000` and `--bench-frames 4500` — `[BOOT-SM-EDGE] #6 case 5 -> 6 … vf=977/979`, NO further edge by vf 3000 / 4500 (75 s), `[VU1-HLE-RT]` 0 / 22 lines; OFF (`PS2_EE_RUNTOKEN=0`): `--bench-frames 3000` — `#7 case 6 -> 7 … vf=2629`, 266 `[VU1-HLE-RT]` lines (title scene). Logs: `/tmp/s126/play/boot2game.log`, `boot4500.on.log`, `boot2game.off.log`. |
| **Subsystem** | threading (EE run token / EeEventQueue) — secondary: kernel-hle (legacy IOP hosting, kernel OFF), loader |
| **Root cause** | NOT YET ROOT-CAUSED (found in round 1B's last leg, bounded session). Hypothesis consistent with PHASE0_IMPL §11.6 item 5 and BUG-035's modelling rule: in PLAY the IOP kernel is OFF, so STREAM.IRX's threads are foreign host `std::thread`s whose completions (CD deliveries / RPC end-callbacks / heartbeat) are routed through `EeEventQueue` and applied only when a PARKED guest holder drains (park poke → `BlockEnd` → post-acquire drain). The post-FMV title load is the boot loader-SM poll (0x2b4738 hook): if the holder spins there without a kernel scheduling point — or every guest thread is in a host-side wait that is not a kernel park — the queued wakes are never applied and the load never completes. The deterministic profile cannot see it: it runs kernel ON (frame policy) where the boundary sequence drains the queue every frame, and its cold-boot leg is 1500 vf (< vf 2629). Same class as the BUG-026 realtime stall (holder spins, queue undrained), different producer. |
| **PS2 rule violated** | Interrupt/RPC completions land in the EE's stream at defined points; an EE busy-wait on hardware/IOP state must observe the completion. |
| **Fix + hatch** | OPEN. Repro first with `PS2_EESCHED_DIAG=1` on the ON arm from vf ~1600 (FMV end) — which thread holds the token, what it polls, how many `enq` lines pile up undrained — then either give the loader poll a scheduling point that drains (`DrainQueuedEventsIfPending()` on the holder at the poll site) or fire the legacy hosting's deliveries as `kDeferred` ticks at the EE park sites. Interim play option: `PS2_EE_RUNTOKEN=0` restores the 2026-09-24 play path. Profile dependency stated truthfully [record fix 2026-09-26]: at round 1B the deterministic profile did NOT set `PS2_EE_RUNTOKEN` — the battery and the frozen baselines relied on the binary's shipped default (ON-unless-0), so a play-default flip to `=0` would have silently changed the gate's configuration. Since 2026-09-26 `profile_deterministic.py` pins `"PS2_EE_RUNTOKEN": "1"` explicitly; the baselines' `env_hash` was re-stamped (`0x09d513b97f30f7ea → 0x9a0f815a02d994d4`) with the hash streams proven unchanged (`verify/baseline/README_FREEZE.md`, PHASE0_IMPL §12.7). |
| **Regression test** | `tools/coldboot_gate.py` must grow a **title-reached** assertion: `--frames 3200` and require the `[BOOT-SM-EDGE] … -> 7` line (or luma-class change to the 3D title) — the luma gate at f900 cannot see this class (the FMV is bright, the injector keeps presenting). |
| **Source record** | PHASE0_IMPL.md §12.6 (round 1B). |
| **Triage tips** | A cold boot whose FMV audio completes (`fmv_c` plateau) but whose `[BOOT-SM-EDGE]` stops at case 6 while `[VU1-HLE-RT]` never appears = "title load never completes"; compare with `PS2_EE_RUNTOKEN=0` first — if that reaches case 7, it is the token/queue class (this entry / BUG-035 family), not the loader or the ISO. |
