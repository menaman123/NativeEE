# BUG-026 — Snapshot sharing served stale texture bytes: epochs stamped before data, undercounted, or never stamped

| Field | Content |
|---|---|
| **ID** | BUG-026 |
| **Title** | [M1A-EPOCH]/[M1A-DEPBRACKET] The snapshot-share fast path trusted page epochs that lied three ways: EE transfers stamped BEFORE data landed, dbw>rrw swizzle overhang undercounted the stamped span, and GFX deposits stamped AFTER data (plus wholly unstamped writers: SyncZToVRAM, CLUT restore, gs_hle fallback, savestate restore) |
| **User-visible symptom** | Sporadic stale-texture serves under the snapshot-share fast path (`PS2_GL_FAST` family) — textures one-or-more updates old, load/timing dependent. |
| **Scene / savestate** | `slowspot` + `slot44` island anchors; `PS2_SNAPVERIFY` oracle (compares every reuse against a fresh decode). |
| **Subsystem** | gs-vram (primary), savestate |
| **Root cause** | The epoch machinery that admits snapshot reuse had ordering and coverage holes: (i) EE transfer paths bumped the page epoch before the bytes were written (a racing reader revalidated against the NEW epoch but read OLD bytes); (ii) the `[min,max]` watermark re-stamp undercounted when dbw>rrw (swizzle overhang wrote pages outside the stamped span) and overcounted disjoint uploads (see BUG-017 layer 2); (iii) GFX deposits stamped after data with no bracket, and several writers (SyncZToVRAM, R197-D2 CLUT restore, the gs_hle fallback copy, savestate restore) stamped nothing at all — restored states could reuse pre-load snapshot bytes. |
| **PS2 rule violated** | Stream-order observability, cache edition: a cache may serve bytes only with proof no writer landed since the cached copy — the epoch must change whenever window bytes changed, at every point a capture can observe them, with publication ordering (begin-publish → mutate → end-stamp). |
| **Fix + hatch** | `[M1A-EPOCH]` write-exact tracker: `NoteVramWrite(addr,bytes)` at the ACTUAL swizzled writes (WriteHWReg legacy loop, [R119-F5] fast path, local→local writePixel, gs_hle fallback), re-stamping exactly the written span at six boundary sites; savestate restore stamps all 512 pages. `[M1A-DEPBRACKET]`: deposits publish seq BEFORE mutation, stamp pages then publish after; capture reuse requires inflight==0; quiescent-only caching. Snapshot share flipped default-ON behind `PS2_GS_SNAPSHOT_FAST` (=0 restores pre-flip regime, ~4x slower on slot44). Post-refactor: `upload_epoch`/`deposit_epoch`/`state` per PageRecord with the commit bracket (ARCH §4.3) — the design IS this fix. |
| **Regression test** | `PS2_SNAPVERIFY` mismatches=0 on full uncapped legs, both anchors (slowspot 598,016 reuses/0; slot44 1,935,360/0); [GB4] save-time zero-stale check; equivalence ctest suites for the r121+ members. |
| **Source record** | `Ps2Recomp/docs/loop_state/MIDDLE_NATIVE_IMPL.md` ([M1A], [M1R] audit, M2 verification) |
| **Triage tips** | For any cache admission by version/epoch, audit the three orderings: stamp-vs-data on the writer, span coverage (exact vs watermark), and writer completeness (grep every byte-writer for a stamp call). Build the SNAPVERIFY-style oracle FIRST — "reuse must equal fresh decode" converts staleness from a visual mystery into a counted mismatch. |
