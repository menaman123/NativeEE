# BUG-063 — Stale-display present stand-in: the title's per-frame `0x70000 → 0x0` display composite is not reproduced on the host, so the true DISPFB buffer holds a stale pre-scene image and the main buffer is presented instead

Filed by integration stage IDOC-A (2026-10-01) from the phase record's BUG-KB candidate row (source record below); the record stays the evidence.

| Field | Content |
|---|---|
| **ID** | BUG-063 |
| **Title** | Stale-display present stand-in: the title's per-frame `0x70000 → 0x0` display composite is not reproduced on the host, so the true DISPFB buffer holds a stale pre-scene image and the main buffer is presented instead |
| **User-visible symptom** | Without the stand-in: the display shows a stale pre-scene image (the last picture written to FRAME 0x0) while gameplay renders unseen into the main buffer. With the stand-in (OLD and NEW): the main buffer is presented — correct-looking frames by a heuristic (display target idle > 30 frames, main buffer drawn ≤ 16 frames ago) |
| **Scene / savestate** | every in-scene anchor (the stand-in is live on the title's main frame buffer); OLD's own comment names the render-graph fact: "the drawn render-graph has zero draws to FRAME=0x0 in-scene" |
| **Subsystem** | `gs-present` (primary); `gs-classes` / `gs-vram` (secondary: the dropped composite is a draw classification or a local→local transfer) |
| **Root cause** | OLD `host_app/graphics/opengl/opengl_backend.cpp:24339-24385` `[SCANOUT-STALE-OVERRIDE]`; NEW `engine/gs/hle/present/scanout_composer.cpp` `ScanoutComposer::PickSource` + `VramLayout::main_fb_fbp` (profile data, `games/<title>/renderer_profile.cpp`) + the named ages `kStaleDisplayFrames` (30) / `kFreshWorkFrames` (16). Suspected defect (OLD's own comment `:24344-24350`): the game's per-frame `0x70000 → 0x0` display composite (one full-screen textured draw / local→local transfer per picture) is not reproduced on the host, so the true display buffer keeps a stale pre-scene image while the main buffer is composited fresh every frame; the stand-in presents the main buffer instead (with the DISPFB-format round trip through the mirror when the classes differ). |
| **PS2 rule violated** | The CRTC displays exactly DISPFB — the buffer at the DISPFB1/2 address in the DISPFB format, nothing else. |
| **Fix + hatch** | WORKAROUND class (HOOK_RECLASSIFICATION §3.10, carried row L1): the stand-in. Root-fix plan: locate the dropped composite — a draw classification that discards the FRAME=0x0 draw, or a local→local transfer the transfer engine does not execute — and remove the stand-in once the composite reaches 0x0. Expiry gate: the 12-leg frames lane (the stand-in must be inert on every leg once the composite lands; it also moves the mirror — the stand-in deposit lands at the scanout base — so the mem lane is a secondary witness). No env var |
| **Regression test** | ctest `Present_DrawScanoutSource` (stale-display cases + probe P13) |
| **Source record** | `docs/phases/PHASE6_IMPL.md` "Ledger deltas owed at integration" L1 (6D‴, Review 6D″ fix 2), findings row `P6-STALE-DISPLAY-PICK` (`:112`), item 7 L7; `docs/design/HOOK_RECLASSIFICATION.md` §3.10; HACK_LEDGER §9 L2 (the `ScanoutFromVRAM` FMV hold reached only through this round trip) |
| **Triage tips** | If the presented image lags the scene (stale title screen under gameplay) check `ScanoutComposer::PickSource`'s ages; if gameplay looks right but `mem` lane deposits land at the scanout base, that is the stand-in moving the mirror — the root fix is the missing FRAME=0x0 composite, not a tweak of the ages. |
