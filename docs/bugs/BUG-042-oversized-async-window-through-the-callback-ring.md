# BUG-042 — Oversized asynchronous loader window routed through the callback ring in NEW: the title's completion copy reads past the ring's end into the destination (coldboot frame-63 runaway record parse)

| Field | Content |
|---|---|
| **ID** | BUG-042 |
| **Title** | NEW's `LoaderFileIo::WindowedRead` staged the completion copy (`fs+0x10 = dest`, `fs+0x18 = size`) and mirrored the window into the callback ring for EVERY asynchronous read; retail's `FUN_002aac80` does so only for a window below the ring's capacity and DMAs a window at or above it straight to the destination with nothing staged. For the first oversized window (`0x50b38` bytes through the `0x10000`-byte ring, frame 62) the title's completion `FUN_002ad110 → FUN_002b5dd8` therefore copied `0x50b38` bytes from the ring base, i.e. `0x40b38` bytes of whatever lies past the ring (the previous DATA.BH read) into `dest+0x10000..`, and the record parser then read a garbage string length from that tail |
| **User-visible symptom** | Cold boot (deterministic profile, memory lane): the leg passes boundary 60 (`mem.mhash 60,0x8d000860de96f0b5`) and stops at `frames.fhash` line 63 with one core spinning in a byte-wise `memcpy` writing outside RAM (`FUN_002c6ce0 ← FUN_002b5dd8(stream=0x70003e40, dest=0, n=0xffffff6f) ← FUN_001bb710 ← FUN_001c0670 ← FUN_001a6ac0 …`), `run.meta finalized=0`, no image past 60 (INT-I410C-F63-RUNAWAY-COPY). |
| **Scene / savestate** | coldboot leg, `--frames ≥ 64 --profile deterministic`; the second asynchronous read of the title (`DATA.BD+0x2265d`, `0x50b38` bytes → `dest=0x00fc4b00`, fs `0xbb35a8`, stream `0xbab59c {base 0x972340, cap 0x10000}`) issued in frame 62, delivered at boundary 62/63. |
| **Subsystem** | cdvd-loader |
| **Root cause** | Retail `FUN_002aac80(fs, off, size, dest, sync, status)` (ELF `0x2aac80-0x2ab138`), on the "ring window not valid" branch (`fs+0 & 0x40000` clear, `0x2aafa4`): with a callback stream (`cb = fs+0x14`) and `size < cap` (`cb vtbl+0x3c` = `cb+0x10`; `sltu v0, s4, v0` at `0x2aafc4`) it rewinds the cursor (`vtbl+0x54`: `cursor = base`), stores the window's file position at `fs+0xc`, DMAs `min(file remaining, cap)` bytes INTO THE RING (`FUN_002ad9a8(fs, pos, n, base)` at `0x2ab048`, `a3 = lw 8(cb)`), stages `fs+0x18 = size`, `fs+0x10 = dest` (`0x2ab090-0x2ab094`) and sets `0x40000`; the completion (`FUN_002ad110`, or the sync wait `FUN_002ad1a0`) then copies `size` bytes ring → dest (`vtbl+0x14 = FUN_002b5dd8`: `memcpy(dest, cursor, n); cursor += n`) and zeroes `fs+0x10`. With no stream, or `size >= cap`, it DMAs straight to dest (`FUN_002ad9a8(fs, pos, size, dest)` at `0x2ab0c8`, `a3 = s5`), writes neither `fs+0x10` nor `fs+0x18`, leaves the ring and cursor untouched, and the completion therefore copies nothing (`fs+0x10 == 0`). NEW's seam (which replaces the body) applied the through-ring bookkeeping unconditionally and bounded only the ring FILL by `cap` — so the title's copy of `size` bytes from a `cap`-byte ring imported the bytes past the ring's end into the destination's tail (`dest+0x14263` = the string header the parser read as `0xffffff6f`). OLD (read-only) has the same unconditional staging and survives only through its `0x2ad110` dest-preservation hook (`main.cpp` `[MC-COMPLETION-PRESERVE]`: saves/restores dest and the ring cursor across the completion body). |
| **PS2 rule violated** | The title's own windowed reader routes a window by its size against the callback ring's capacity: below the capacity the window is DMAed into the ring and copied out at completion; at or above it the window is DMAed to the destination directly and no completion copy is staged. A model replacing that body must reproduce the routing, not only the ring fill. |
| **Fix + hatch** | `LoaderFileIo::WindowedRead` (`games/<title>/hle/loader_sync/loader_file_io.cpp`, I4.10-E): `through_ring = InRam(cb) && size < *(cb+0x10)`; only then are `fs+0x10/fs+0x18` staged and the delivery `apply` mirrors the window at the ring base and rewinds the cursor; a direct window fills dest only and leaves the ring/cursor alone (census `LoaderFileIo::Census::async_direct`). The slot-status model (BUG-041) is unchanged on both paths (issued at issue, done after the bytes). No hook, no hatch. |
| **Regression test** | `LoaderCompletionOversized` (`tests/cdvd/test_loader_completion_oversized.cpp`, 35 checks): a window three rings long → nothing staged, ring/cursor untouched, the REAL recompiled `FUN_002ad110` (through the dispatch table, with the stream class's vtable words `0x306b50+0x10/+0x14`) answers pending while in flight, then done with NO copy — dest stays the file bytes and the bytes planted past the ring's end never reach `dest+cap`; a window below the capacity → staged, ring at base + cursor rewound at delivery, the REAL completion copies `size` bytes and advances the cursor by `size`, zeroes `fs+0x10`, lowers the flag; a window exactly the capacity is direct. Without the fix 11 checks fail (`big_dest_still_file_bytes_after_completion`, `big_no_ring_tail_in_dest`, …). Leg-level: the coldboot leg passes frame 63 (73 `frames.fhash` lines before the next, unrelated stall). |
| **Source record** | `docs/phases/INTEGRATION_IMPL.md` §I4.10-C (INT-I410C-F63-RUNAWAY-COPY), §I4.10-E (attribution with lldb: the `FUN_002b5dd8` breakpoint trace `f63_bp.log`, the retail disassembly `disasm_aac80.txt`); OLD (read-only) `host_app/hle_heap.cpp:1412-1500` (`[CB-STREAM-FIX]`, cap-bounded fill), `host_app/main.cpp` `[MC-COMPLETION-PRESERVE]` / `[STREAM-CURSOR-PRESERVE]` (the hook this model replaces). |
| **Triage tips** | A `FUN_002b5dd8` call with `n > cap` of its stream (`a0+0x10`) from `ra = 0x2ad16c` is the completion copying an oversized window — check `fs+0x18` against the stream's cap at the preceding `WindowedRead`; a later garbage `FUN_002b5dd8` from the record parser (`ra 0x1bb7c0`, `n` ≥ `0x80000000` or `dest = 0`) whose cursor is more than `cap` past the delivered buffer's base is the consequence. `run.meta`/census: `async_direct` must count every async window with `size >= cap`. |
