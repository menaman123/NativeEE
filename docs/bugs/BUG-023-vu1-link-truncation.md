# BUG-023 — Camera-direction fps collapse + missing gas geometry: VU1 mesh-list links truncated to 10 bits

| Field | Content |
|---|---|
| **ID** | BUG-023 |
| **Title** | [D5 / PS2_VU1_LINK11] The VU1 HLE/cached tiers masked mesh-node link addresses with &0x3FF — links ≥0x400 wrapped, so big rings declined the HLE every exec and the fallback walked garbage until the 1M-cycle watchdog truncated it (dropped XGKICKs) |
| **User-visible symptom** | In the cavern, fps drops whenever the camera faces one direction; gas-scene geometry can be incomplete (dropped kicks) in every env. |
| **Scene / savestate** | `save_states/slowspot_f35613_s1789341953.ps2st` (cavern, faces the slow direction), `slowspot_f29548_s1789326538.ps2st` (gas). |
| **Subsystem** | vu1-hle |
| **Root cause** | VU1 data-memory node lists address 16 KB = 1,024 quadwords, needing 10 bits — but the game's rings span regions where links carry 11 significant bits. Four sites masked links with `&0x3FF` (10 bits), wrapping any link ≥0x400: node walks left the real ring, guards (`mesh_guard < 64`, `gate pre-scan g < 64`) tripped, the HLE declined EVERY exec, and the cached-interpreter fallback walked the corrupted ring until the shared 1,000,000-cycle watchdog truncated the program — burning ~1M cycles per exec (the fps collapse) and dropping the tail XGKICKs (missing geometry). Two companion link-constant bugs: gate links computed with a wrong +8 formula (0x305→0x306, 0x44A→0x44B, trace-proven). Camera-direction dependence = ring content varies with facing. |
| **PS2 rule violated** | VU1 addressing: VU memory pointers/links are 16-bit fields addressing quadwords; masking beyond the architecture's own wrap (16 KB = 0x3FF quadwords is the SIZE, but link fields here carry byte-granular/extended encodings needing 11 bits per the game's convention) must follow the MICROCODE's own arithmetic, not a guessed mask. `[title-idiom]` for the exact field widths; generic lesson: replicate the micro's arithmetic bit-for-bit. |
| **Fix + hatch** | `PS2_VU1_LINK11` (default ON; =0 restores &0x3FF): mask 0x7FF at all four sites via shared `VuLinkMask()` (vu_fast_exec.h — interp + cached + AOT TUs inherit it); corrected gate links; `PS2_VU1_CRYS_GATE` (default ON) retires the pre-scan decline in favor of in-body gating; fixed-64 guards replaced by the micro's own data-driven termination (IBNE pm == mesh_end) + generous safety bound; offline oracle cycle cap raised (env-hatched) so --exact proofs run untruncated. Post-refactor: library entries carry `oracle case ids`; the replay oracle re-proves each lifted program (D5 VU1 library API). |
| **Regression test** | vu1_replay --hle over the captured ring cases (FAIL=0); per-direction fps before/after; VU sweep 3,293 cases; watchdog-truncation counter = 0 on the anchor legs. |
| **Source record** | `Ps2Recomp/docs/loop_state/CAVERN_DIRECTIONAL_IMPL.md` (prime-suspect §, [D5] fixes) |
| **Triage tips** | Direction/content-dependent fps cliffs in VU scenes = a decline storm: check fallbacks==execs first, then WHY the HLE declines. An exec that burns EXACTLY the watchdog limit is walking corrupted data, not doing work. When lifting microcode by hand, transcribe address arithmetic bit-exactly — a "safe" mask narrower than the micro's own is a data corruption. Fixed-iteration guards must mirror the micro's own termination condition. |
