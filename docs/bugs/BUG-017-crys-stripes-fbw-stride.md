# BUG-017 — Crystal environment stripes: dual-view lane deposits written at the wrong FBW stride (plus polluted page epochs)

| Field | Content |
|---|---|
| **ID** | BUG-017 |
| **Title** | [CX8-STRIDE] SyncRTToVRAM encoded with `fbw = target.width` unconditionally — the CT24 view (fbw=256) of a CT16-grown (fbw=512) target was deposited at 8 pages/row while its consumer decodes at 4: page-row-displaced, band-interleaved mirror content |
| **User-visible symptom** | 32-row-granular horizontal band structure on the crystal's environment layer (red/yellow crystal close-ups); bands are not merely old content — they are structurally displaced (decoded row 64 == FBO row 32). |
| **Scene / savestate** | `ps2state_slot0_f46203_red_crystal.ps2st`, `ps2state_slot0_f46949_yellow_crystal.ps2st`; forced-arm reads scoped `280000:1:8:8` (the crys env CT24 256x256 read). |
| **Subsystem** | gs-vram (primary), gs-targets |
| **Root cause** | Three stacked layers. (1) Stale mirror serving (BUG-016's class). (2) Page-coarse, polluted epoch decline: `r119::WindowEpoch(tbp, tex_size)` spanned the target's GROWN footprint including the 0x2c0000-0x35ffff streamed-tile band the read never touches, and the `[M1A-EPOCH]` watermark re-stamp bracketed disjoint uploads into one span — pages stamped with epochs no write produced. (3) THE stride defect: the fog/env lane is DUAL-VIEW (CT16 draws at fbw=512 grew the target; the CT24 view is fbw=256); every mirror deposit of the 32-bit view was encoded at the target's 512-wide stride (8 pages/row) while the CT24 tbw=256 consumer decodes at 4 — ANY deposit era produced garbage bands, proven by meandiff 0.0 at the matched row offset. |
| **PS2 rule violated** | GS addressing: a buffer's page layout is a function of ITS OWN FBW/TBW, per view — two views of the same bytes have different page-per-row geometry, and a deposit must be encoded in the geometry of the bytes' stream-order author, not the target record's grown width. |
| **Fix + hatch** | Encode deposits at the authoring view's fbw; replace the watermark re-stamp with precise sub-page write-bits (`write_bits: u64` [CX8]); scope decline predicates to the READ's footprint. The "RT-backed reads never consume stale mirror bytes" rule hardened in `rt_neverstale.h`. Hatch family `PS2_S32_FORCESTALL / PS2_FTT_FORCE_DECLINE` gained scoped forms (`:tbp:psm:twlog:thlog`) as the discriminator. Post-refactor: VramImage PageRecord.write_bits + per-view xfer geometry (ARCH §4.3, gs/xfer). |
| **Regression test** | BASE2-vs-BASE bit-identical presents (exact-equality bar); scoped forced arms quantify each layer; corpus byte-identity; the read-footprint math (`uv_bbox`) unit-covered. |
| **Source record** | `Ps2Recomp/docs/loop_state/CAVERN_CRYSTRIPES_IMPL.md` ([CX8], [CX8-STRIDE]) |
| **Triage tips** | Banding with a fixed row period (32 rows = one CT24 page row) is stride/geometry, not content: overlay the decode at candidate offsets — meandiff 0.0 at some offset proves displacement. When epochs "should" protect but don't, audit the epoch WRITER for coarseness (watermarks, grown footprints): a protection that stamps too much protects nothing. |
