# BUG-006 — Shadows displaced, then gone: the ALT16 companion absorb imported EE-future and torn VRAM bytes

| Field | Content |
|---|---|
| **ID** | BUG-006 |
| **Title** | [SH5] RefreshFBOFromVRAM's full-band CT16 absorb read live `gs_vram` from the GFX thread while the EE ran frames ahead — importing future/torn bytes into the shadow-mask pair FBOs |
| **User-visible symptom** | Character blob shadows displaced from actors (moderate load) or completely gone (heavy load); severity varied with machine load; replays looked different from live. |
| **Scene / savestate** | `save_states/ps2state_bad_shadows.ps2st` (sha256 26e6a83a…); live legs vs `bad_shadows` corpus replay. |
| **Subsystem** | gs-vram (primary), gs-targets |
| **Root cause** | The T8H shadow-composite serve rides pair FBOs refreshed by `RefreshFBOFromVRAM`, which ran a FULL-band (rows 0-448) CT16 decode of LIVE `gs_vram` into both pair FBOs EVERY frame. `gs_vram` is written by the EE THREAD at transfer time; under load the EE runs frames ahead of the render queue, so the absorb imported EE-FUTURE and mid-write-TORN bytes (row-band census: 66.4k alpha population vs 30.8k healthy — 2.2× junk). Causal proof: disabling the absorb (`PS2_SH5_ALIASEPOCH=2`) restored replay-matching bands. Displacement = future silhouette content under this frame's draws; disappearance = torn imports degrading index lanes toward CLUT rows with As≈128 (invisible under ALPHA 1000). A second same-family defect: the `[SH1-LASTWRITER]` writeback tiebreak used `up_epoch > batch_epoch`, letting an EQUAL epoch steamroll a just-uploaded mask. |
| **PS2 rule violated** | GS stream order: a read of local memory observes the bytes as of ITS position in the register-write stream — never a later writer's bytes, never a torn word. Cross-thread mirrors must be consumed at queue position (as replay does), not at wall time. |
| **Fix + hatch** | `[SH5-ALIASEPOCH]` (default ON): stream-order page guard on the CT16 absorb — 8 KB pages whose EE upload epoch is NEWER than the job's carried epoch keep the FBO's own rows; epoch-0 pages absorb verbatim (replay-neutral by construction). `[SH5-TIEBREAK]`: yield-to-writeback requires the upload STRICTLY older (`up_epoch >= batch_epoch` keeps protection; `up_epoch==0` still yields). Post-refactor: VramImage single-writer commit + freshness fields in TextureSource (ARCH §4.3/§4.5). |
| **Regression test** | 3 repeated live legs 0 FATAL on bad_shadows; row-band census replay-matching; corpus byte-identity. INVARIANTS: the ReadView/epoch-arbitration rules (A3 invariants 4-8) as named tests. |
| **Source record** | `Ps2Recomp/docs/loop_state/PLAYTEST_R1_IMPL.md` (§ [SH2][SH3][SH5]), `SHADOW2_IMPL.md`, `SHADOW2_ROOTCAUSE.md` |
| **Triage tips** | Live-vs-replay divergence that scales with machine load = an EE-ahead staleness window; diff the same censused rows live vs replay. When a "refresh from mirror" exists on the GFX thread, ask what epoch the mirror bytes carry — an unguarded absorb is a time machine. Equal-epoch tiebreaks matter: pick the direction that preserves the just-written data. |
