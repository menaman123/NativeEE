# BUG-085 — A cold-boot boundary image of the original tree restores byte-exact but never resumes (no EE boundary follows the restore)

| Field | Content |
|---|---|
| **ID** | BUG-085 |
| **Title** | `--load-state` of an original-tree boundary image taken from a cold boot (`old_b120`, `old_b2700`, `old_b3780`) restores byte-exact (`restore.mhash` = the lane's line) but no frame boundary ever follows: the EE spins inside the title's allocator and the leg is killed by the stall watchdog |
| **User-visible symptom** | A resumed title/loading-screen image shows nothing (black, no present) forever; the harness leg has 0 `frames.fhash` lines and `run_bounded` exits 125 (`no growth of frames.fhash for 40s`). The 11 gameplay anchors resume fine. |
| **Scene / savestate** | `verify/baseline/coldboot/probe/old_b120.ps2st` (the loading screen, boundary 120), `verify/baseline/coldboot_attract/probe/old_b2700.ps2st` / `old_b3780.ps2st` (the title idle); any `--frames N`. Reproduction: `python3 -u verify/run_leg.py --repo <NEW> --binary build/app/host/nativeee --anchor verify/baseline/coldboot/probe/old_b120.ps2st --frames 3 --out <wd> --tree new --game-files <OLD>/game_files --timeout 60 --stall-s 20` (pre-fix: exit 125, `restore.mhash` = `74bacf01b589b5a6`, 0 lane lines). |
| **Subsystem** | `savestate` (primary), `ee-mem` (the META arena workaround) |
| **Root cause** | **NAMED (P8.27-A).** The HEAP savestate section was never restored. Its payload is the original tree's HLE-heap bookkeeping followed by the META arena's bookkeeping (`hle_meta_arena::SerializeState`: capacity, per-cell state, bump, quarantine, counters). The META arena (`games/…/hle/workarounds/meta_arena.*`) is where the title's compacting handle heap keeps its 0x20-byte record descriptors, its 0x18-byte compaction-job object and its deferred-op nodes (the `FUN_00181560(size ≤ 0x20)` allocations from the pool code `0x202000–0x206000` are routed there). NEW restored the arena BYTES (the META section, 2 MB) but had no owner for HEAP, so `MetaArena::bump_` stayed 0 after every restore. The first routed allocation after the restore (`MetaArena::Alloc`) therefore re-vended **cell 0 = guest `0x0200000c` = the title's live compaction-job object** (`*(pool 0x31b138 + 0x8144) = 0x200000c` on every image). The compactor step `FUN_00205588 → FUN_002029d8(job)` then read a job whose fields were a fresh descriptor's, and its copy step called `memcpy(0x2e807f, 0x2e8080, 0x8000)` (lldb watchpoint on the host bytes of guest `0x2ea46c`: `_platform_memmove ← Libc::Memcpy ← FUN_002029d8 (ra 0x202a60) ← FUN_00205588 ← FUN_0017d6b8 ← FUN_0017d558 ← FUN_0017ce50 ← DispatchTable::InvokeAt ← ThreadRelauncher::WalkChain`) — a one-byte-shifted copy over the title's allocator bin table `0x2ea070+8i` and the pool header `0x31b138` (zeroed). The next `FUN_001816c8()` saw a null pool and tried to allocate the 17 MB pool anew (`FUN_002c7718 → FUN_002cbf98`, size `0x010a3d80`, bin 126); the bin walk `r16 = *(r16+0xc)` followed the shifted link `0` and spun (`memory::read<unsigned int>(address=4)` — the BUG-068 signature). The gameplay anchors never allocate pool metadata in their legs, so they never met it. The thread-chain hypothesis of INT-P826B-RELAUNCH-CRT0-CHAIN is refuted: `ThreadRelauncher::WalkChain` re-entered the crt0-rooted 5-frame chain correctly (the `sample` stack shows the main loop `FUN_0017ce50` running under `WalkChain` level 3); the crt0 root `(0x100008, ra 0)` is simply never reached (the title never returns to crt0). |
| **PS2 rule violated** | A savestate must restore the ALLOCATOR STATE together with the memory it manages: every allocation made after the restore must land where the saved run's would have (the original tree's own comment on its HEAP section: "Without this, post-load allocations alias objects the restored guest still holds — the resume-crash class"). `[title-idiom]` for the arena itself (a quarantined workaround), but the rule is general. |
| **Fix + hatch** | `engine/ee/savestate/heap_section.{h,cpp}` (`HeapSection`): the HEAP owner — part 1 (the original HLE-heap grammar: four bounds words, `n_free` pairs, `n_alloc` pairs) is parsed structurally and skipped (NEW keeps no such heap; on save it is written EMPTY, 24 bytes of the same grammar), part 2 is handed to a tail codec the composition root supplies (`app/host/ee_bootstrap.cpp`: `MetaArena::SerializeState / ValidateState / RestoreState`); the section is OPTIONAL (an image without it restores as before). run.meta `heap_section_restored=`, `meta_arena_bump_restored=`. No toggle: a construction gap (the original always restored it). |
| **Regression test** | `SavestateHeapSection` (unit: the grammar, the empty prefix, bump 644 / quarantine 10 round-trip, the first post-restore allocation is cell 644 not cell 0; through `StateRestorer` without the owner bump stays 0 = the RED shape, with it 644); `RootColdbootProbeResumes` (`old_b120 --frames 61`: finalized, `heap_section_restored=1`, `restore_mhash` = lane line 120, the first resumed frame's hash = the cold-boot lane's frame 121 `0x91112b3860dce5fc`; ≈ 2–3 s Debug). |
| **Source record** | `docs/phases/PHASE8_IMPL.md` P8.27-A (`int_work/p827a/`: `attr/s.sample`, `attr/lldb2.out`, `attr/wp.out`, `attr/heap_bins.txt`, `thrd_records.txt`); the finding rows INT-P826B-RELAUNCH-CRT0-CHAIN, INT-P825T-OLD-TITLE-PROBE-RESTORE-STALL, INT-P823A-OLD-IMAGES-NOT-RESUMABLE-ON-NEW (all this defect). |
| **Triage tips** | A restored image that runs but corrupts memory within the first frame while the anchors are fine: list the sections the file carries that NO registry owner claims (`state_hash.parse` tags vs `SectionRegistry::Specs`) — a skipped section is host-side bookkeeping the guest depends on. A one-byte-shifted copy of a table = a `memmove` whose descriptor was re-vended: watchpoint the host bytes of the corrupted guest word (`watchpoint set expression -w write -s 4 -- (char*)RecompAbi::Memory().Ram().Data()+0x<addr>` after `breakpoint set -n ThreadRelauncher::Relaunch`) and read the memcpy's `a0/a1/a2`. `FUN_002cbf98` spinning on `address=4` is the CONSEQUENCE (BUG-068's signature), never the cause. |
