# BUG-030 — ~1 s green garbage overlay: a streaming hitch sent the present-pass read to a CPU decode of never-faithful mirror bytes

| Field | Content |
|---|---|
| **ID** | BUG-030 |
| **Title** | [S32-RTKEEP] FindTargetTexture's CPU-dirty fallback (`!recently_drawn && ArePagesCPUDirty → return 0`) demoted the scanout work-buffer read (tbp=0x70000, CT24 view of the CT32 scene) to a gs_vram decode whenever a hitch stalled the draw cadence past the 2-frame carve-out |
| **User-visible symptom** | Transient (~1 s) green garbage / stripes over the whole scene during streaming hitches (island window F7256-7293: 17 % of bytes non-live). |
| **Scene / savestate** | `artdet_f7288.ps2st` replay state; deterministic repro via `PS2_S32_FORCESTALL=<vf0>:<vf1>` (forces the !recently_drawn arm). |
| **Subsystem** | gs-texsrc (primary), gs-targets |
| **Root cause** | The present pass reads the scene RT (0x70000) as CT24. The serve had a 2-frame recently-drawn carve-out; a streaming hitch stalled the scene-draw cadence past it while writeback/alias churn kept the pages CPU-dirty, so the early-out sent the read to a CPU decode of `gs_vram` — which is never a faithful scene copy for a GPU-authored target (the mirror is lazily deposited by design). One stale decode per present frame × 61 frames = the green second. |
| **PS2 rule violated** | The never-stale rule again, presentation edition: a read whose last stream-order author is a live render target must serve that target's content — the mirror is only authoritative for pages the GPU never authored. |
| **Fix + hatch** | `[S32-RTKEEP]` (gate `PS2_GS_RTKEEP`, default ON; =0 legacy early-out exactly): at the pinned early-out, KEEP serving the live FBO when epoch evidence allows (epoch equal/older/virgin keep; newer-upload/bpp-incompatible/invalid/gate-off never keep) — contract identical to the existing age≤2 serves which already serve with dirty=1. One-shot log note on keep. Post-refactor: `last_draw_gfx_epoch` serve-keep predicate in RenderTarget CoherenceState (ARCH §4.4 [S32-RTKEEP]); the ResolveRead decline ladder makes "decline ⇒ rescue before Decoded fallback" structural ([S109]). |
| **Regression test** | `tests/test_s9_shadow.cpp` — 7 RtKeepServe vectors (73 checks); forced-stall discriminator: LEGACY 61 decodes of 0x70000 / FIX 0 over the same window; `VsUvEquivalenceAlt16Off` ctest (full byte-equivalence corpus on the legacy branch). |
| **Source record** | `Ps2Recomp/docs/loop_state/TEXCORRUPT_IMPL.md` (§2 [S32-RTKEEP]), `TEXCORRUPT_REPORT.md`, `TEXCORRUPT_REVIEW.md`, `TEXCORRUPT_BRIEF.md` |
| **Triage tips** | Whole-screen garbage that appears under LOAD and self-heals = a fallback path serving during a stall, not a corruption: census which serve route the present-pass read took per frame. Time-window carve-outs (age ≤ N frames) are load-sensitive by construction — replace them with evidence predicates (epochs/authors). Build the FORCESTALL-style deterministic discriminator before and after: a fix you can't force is a fix you can't prove. |
