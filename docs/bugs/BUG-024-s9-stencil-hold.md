# BUG-024 — Crystal-room shadows misrendered: the S9 ladder's own pre-draw flush consumed its own deposit mid-sequence

| Field | Content |
|---|---|
| **ID** | BUG-024 |
| **Title** | [GS-S9DEM hold] Mid-fiction, the S9 stencil ladder's kPreDraw flush acquired the armed accumulator's OWN pending deposit — encoding pre-strip bytes and demoting 40,923 stencil strips to the color path |
| **User-visible symptom** | Crystal-room (and slowspot-episode) shadow composites wrong: stencil strips render as color writes — shadow volumes visible as colored geometry / wrong accumulation instead of the quantized shadow mask. |
| **Scene / savestate** | Crystal replay + `s57_walk`/`slowspot` corpus captures; live crystal scene legs. |
| **Subsystem** | gs-classes (primary), gs-vram |
| **Root cause** | The S9 seven-pass composite ("the fiction") arms a CT16S accumulator and draws DATE-gated stencil strips into it before the designed QUANT trigger encodes the result. The generic texture-over-GPU-dirty-pages rule made the ladder's own kPreDraw flush acquire the accumulator's pending deposit MID-SEQUENCE — the encode ran on pre-strip bytes, and the ladder's strip classification collapsed (G2 numbers: 402 stencil / 40,923 color pre-fix → 41,325 stencil / 0 color post-fix). The flush that protects every OTHER reader was self-destructive when the reader was the fiction itself. |
| **PS2 rule violated** | GS stream order within a multi-pass idiom: the accumulator's bytes at pass N are consumed only at the recipe's own designed read point (the QUANT pass); no intermediate host machinery may observe/encode the buffer mid-recipe. `[title-idiom]` — the seven-pass recipe is TT's blob-shadow engine; the "don't self-consume mid-recipe" rule is generic to any sequence-detected composite. |
| **Fix + hatch** | `FlushPendingRTSyncs(start, size, reason, reader_pages_only, hold_fbp)` gains a hold: the S9 ladder's own kPreDraw flush passes `hold_fbp` = the armed accumulator's fbp — ONLY when `HoldOn() && state==ARMED && seq_fbp==batch.frame_fbp` (only mid-fiction, only our own entry). The held entry still lands and encodes once, at the designed QUANT trigger, after materialize; cross-target entries still flush. Hatch `PS2_GS_S9RDR_HOLD` (default ON; =0 byte-identical defect arm). Post-refactor: SequenceRecipe state in the renderer profile owns its accumulator's visibility window (D5 renderer-profile API). |
| **Regression test** | S9 ledger counters pinned per scene (s57_walk: strips_stencil=14,198 strips_color=0, hold=0 — never engages on healthy scenes); corpus byte-identity 7/7 + adjudicated slowspot; hatch matrix replay = byte-identical to the pre-fix .gsrep with HOLD=0. |
| **Source record** | `Ps2Recomp/docs/loop_state/CAVERN_CRYSTAL_IMPL.md` (hold design + G1-G4 proofs), `CAVERN_CRYSTAL_REPORT.md`, `SHADOW2_IMPL.md` (the S9 recipe) |
| **Triage tips** | When a multi-pass idiom breaks only sometimes, count its per-pass ledger (strips stencil vs color, arms vs materializes): a pass-count anomaly localizes which pass consumed wrong bytes. Generic coherence machinery (flushes, syncs) can be SELF-destructive inside a recognized sequence — the recognizer must own its window. A fix whose counter reads 0 on healthy scenes is correctly scoped. |
