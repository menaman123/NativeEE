# BUG-066 — The IOP FRAME clock is frozen after a savestate restore: the STREAM.IRX heartbeat never beats, finished SFX voices are never released

| Field | Content |
|---|---|
| **ID** | BUG-066 |
| **Title** | After an anchor restore the IOP kernel's FRAME clock is rebased in microseconds but not in frames, so the boundary pump can never advance it; the restored STREAM.IRX heartbeat hard timer (due = now + 16727 µs) never fires and the module's voice-release pass never runs |
| **User-visible symptom** | After loading a gameplay state, SFX voices that had finished keep their SPU voice slots: the one voice OLD keys off within the first two boundaries plays on (slowspot_f40298 v29, f36935 v24, f39807 v25/v28 — audio lane divergent from window W0), and over a few hundred frames the module's 48-record voice pool saturates (artdet: 37/48 type 4 + 11/48 type 1, 0 free by boundary 360) so later key-ons land on other voices or none (artdet W69) |
| **Scene / savestate** | every gameplay anchor restored under the deterministic profile: `save_states/slowspot_f40298_s1789693059.ps2st` (`--frames 6 --state-every 1 --set video.backend=soft`): before the fix `run.meta iop_timer_running=1` but the IOP RAM type bytes `0x12f60..0x12f8f` stay `type1=6, type4=42` on every image and lldb reports `iop_func_0000136c hit count = 0` (the handler), `iop_func_0000a1e0 hit count = 0` (the release pass) over 10 frames |
| **Subsystem** | `iop` (primary: `engine/iop/iop_clock`, `engine/iop/savestate/iopm_section`), `savestate` (secondary), `iop-sound` (symptom) |
| **Root cause** | `IopmSection::ReconcileKernel` rebased the clock with `kernel.Clock().AdvanceToUs(restored_vf * IopClock::kFrameUs)`: `virtual_us_` jumped to the anchor's frame count (40304 × 16667 = 671,746,768 µs) while `IopClock::frames_` stayed at the pre-load value (0). `OnFrameBoundary` is `frames_ += 1; AdvanceToUs(frames_ * kFrameUs)` and `AdvanceToUs` is forward-only, so the boundaries' bases (16667, 33334, …) lay below the rebased time for ~40304 frames and the clock never moved; `FrameCeilingUs()` (= `(frames_ + 1) * kFrameUs`) was likewise below now, so the pump's forced advances were bounded to nothing. The plugin's `RestoreHeartbeat` → `TimrmanModule::RestoreHardTimer` → `IopKernel::StartPeriodicTimerUs` armed the heartbeat with `due_us = NowUs() + 16727` AFTER the rebase, i.e. a due nothing could reach; events due at once (RPC completions, transfers) kept firing, which hid the freeze. The module's worker (`iop_func_000030d4`) runs its release pass (`iop_func_0000a1e0`: type 4 → 1; type 1 with ENVX 0 → 0) only while the tick word `0x12f1c` reads 1, set solely by the heartbeat handler `iop_func_0000136c`. |
| **PS2 rule violated** | The IOP's hard timers (timrman `SetupHardTimer`/`StartHardTimer`, 36.864 MHz / prescale) count real IOP time, which advances with every vsync whether or not a state was just loaded; a restored image resumes with its timers running in the same frame cadence as the saver. The STREAM.IRX heartbeat (compare 0x968c2 at the module's prescale ≈ 16.73 ms, one vsync) therefore beats once per frame on OLD's first boundaries after a restore (`[KSWQ] vf=40304 KOFF core=0 mask=0xfffffc`, `vf=40305 KOFF core=1 mask=0xffffb2`). |
| **Fix + hatch** | `IopClock::RebaseToFrame(uint64_t frames)` (`engine/iop/iop_clock.{h,cpp}`): `frames_ = frames; AdvanceToUs(frames * kFrameUs)` (forward-only as every advance; no-op under Realtime). `IopmSection::ReconcileKernel` calls it instead of the bare `AdvanceToUs`, so the restored anchor's frame count IS the FRAME clock's frame count: the next boundary advances to `(frames + 1) * kFrameUs`, the pump's ceiling is one quantum past it, and a due armed at the restored now is reached within the first pump (inclusive ceiling) — stale pre-load dues (below the new base) still expire at once. No hatch (modelled behaviour); no savestate-format change (`restored_vf` was already supplied to the reconcile). Census: `run.meta iop_hb_beats=<n>` (`IopKernel::TimerBeats()`), `iop_clock=frames=<f>,us=<us>`. Landed by integration stage I8.8-A (2026-10-02). |
| **Regression test** | ctest `IopClockRebase` (`tests/iop/test_iop_clock_rebase.cpp`: after `RebaseToFrame(40304)` one boundary advances by `kFrameUs`; a timer armed at `now + 16727` beats on the second bare boundary / in the first pump; the bare-`AdvanceToUs` contrast never beats in 10 pumps; 9 FAILs without the fix) and root pin `RootAnchorHeartbeat` (`tests/app/root_anchor_heartbeat.py`: slowspot_f40298 6-frame leg → `iop_hb_beats=6`, `iop_clock frames=40310`, `state_b1` type bytes carry no 4, the 41 finished voices Off in the SNDC model) |
| **Source record** | `docs/phases/INTEGRATION_IMPL.md` I8.7-B (`INT-I87B-AUDIO-W0-IS-HEARTBEAT-DEAD`, `INT-I87B-HEARTBEAT-CLOCK-FROZEN`), `docs/phases/DECISIONS_LOG.md` attribution paragraph "the anchors' audio W0 class (I8.7-B)", I8.8-A record (`int_work/i88a/SECTION.md`, `red_run.log`) |
| **Triage tips** | If a restored run shows a periodic IOP timer `running` in run.meta but its handler never hits (lldb `breakpoint set -n iop_func_<handler>` → `hit count = 0`) while RPC completions still arrive, read the kernel clock's `frames=` beside `us=` in `iop_clock`: a microsecond base of thousands of frames with a frame count near 0 is this freeze. Any clock that derives "now" from one counter and "next tick" from another must rebase BOTH at a restore. The residual after the fix: the worker's RPC-woken sweep of boundary 0 clears the restored ENDX latch (`SdSetSwitch(ENDX, 0)`) before the first beat's release pass, so a voice still PLAYING at the save with its ENDX bit set (f40298 v29) is keyed off only when it re-latches (I8.8-A `INT-I88A-RESTORED-ENDX-CLEARED-BEFORE-FIRST-BEAT`). |
