# BUG-039 — OLD `host_app` aborts in `IopKernel::~IopKernel()` during `exit()`; the next launch bundles it into `bug_reports/` (~43 MB per launch)

| Field | Content |
|---|---|
| **ID** | BUG-039 |
| **Title** | Non-bench exits of the frozen `host_app` end in `std::terminate` → SIGABRT from `iop_kernel::IopKernel::~IopKernel()` (static destruction under `exit()`); every following launch's startup crash-scan assembles a `bug_reports/<UTC>_crash/` bundle (~43 MB, incl. a 44 MB slowspot state copy) from the leftover `logs/crash_report.txt` |
| **User-visible symptom** | Quitting the OLD binary in play mode leaves a crash report; each subsequent launch (including every harness leg) grows `bug_reports/` by ~43 MB. Harness legs themselves exit cleanly (`std::_Exit(0)` on the bench path skips static destructors), so the artifacts and `finalized=1` are unaffected. |
| **Scene / savestate** | Any run that returns through `exit()` (play-mode quit, hotkey exit, `--help`-class early exits after the kernel singleton is constructed). Observed 2026-09-26: bundle `OLD/bug_reports/20260926-065023_crash/crash_report.txt` — `[CRASH] Signal SIGABRT (6)` with the backtrace `exit → __cxa_finalize_ranges → iop_kernel::IopKernel::~IopKernel() + 1084 → std::terminate → abort`; bundles at 00:34, 00:46, 00:53 (×2), 01:54 (×2), 02:50 — one per launch since the freeze. |
| **Subsystem** | threading — secondary: iop (kernel host thread teardown), core-log (crash-scan bundling) |
| **Root cause** | NOT YET ROOT-CAUSED (OLD is frozen; this is a construction work item). `IopKernel::~IopKernel() { Shutdown(); }` (`host_app/iop_kernel/iop_kernel.cpp:21`) runs as a static-destructor under `exit()`; `std::terminate` from a destructor is either a joinable `std::thread`/`IopHostThread` destroyed without join, an exception escaping `Shutdown()` while another exception is active, or a condvar/mutex used after its owner was destroyed. The startup bundler (`bug_report.cpp` "crash bundles are assembled at the NEXT launch from the artifacts the handler already wrote") then packages `logs/crash_report.txt` + `logs/ring_crash.rlog` + tails + the most recent `save_states/slowspot_*.ps2st` and truncates the report. |
| **PS2 rule violated** | n/a — host-side lifetime rule: no host thread may outlive the object that owns it; static-destruction order is not a shutdown protocol (ARCH §7: the composition root owns thread lifetimes; `ShutdownLadder` joins in declared order before `main` returns). |
| **Fix + hatch** | OPEN in OLD (never fixed there — REFERENCE_FREEZE). In NEW: `IopHostThread` is owned by the composition root and joined by `ShutdownLadder` (Phase 1 shell, Phase 4 IOP) before any static destructor runs; `IopKernel` has no static instance; the crash-scan bundler is replaced by `core/triage` (Phase 9.2) whose crash-class bundle is assembled by the crashing process's handler-safe path or not at all. No hatch. |
| **Regression test** | Phase 4 `tests/iop`: kernel construct → run → destroy 1,000× in-process without terminate; Phase 8 play check: quit → exit status 0, no `logs/crash_report.txt` written; `tests/core/test_shutdown_ladder`: declared join order. |
| **Source record** | This tree: `docs/REFERENCE_FREEZE.md` "Accepted side effects" (2026-09-26 redirect probe); OLD `bug_reports/20260926-065023_crash/{manifest.txt,crash_report.txt}` (read-only evidence). |
| **Triage tips** | A `bug_reports/*_crash` bundle whose backtrace starts at `exit → __cxa_finalize_ranges` is a TEARDOWN abort, not a gameplay crash — check the bundle's `created_utc` against the PREVIOUS launch's exit, not the current run. Harness legs are unaffected because the bench path `std::_Exit(0)`s after `FinalizeForExit`. |
